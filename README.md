# Бэнэнгская Рапсодия

Караоке-студия: загрузить песню, убрать вокал, разметить текст, спеть
и сохранить видео. Работает в браузере и отдельным приложением
для компьютера.

- **Сайт:** https://gyros-dev.github.io/karaoke-maker/
- **Приложение:** https://github.com/Gyros-dev/karaoke-maker/releases

Ниже — инструкция, как всё это чинить и обновлять самому.
Написана под WebStorm, но команды обычные, подойдёт любой редактор.

---

## Что где лежит

```
karaoke-maker/
├── index.html          ← сайт: разметка
├── style.css           ← сайт: оформление
├── app.js              ← сайт: вся логика студии
├── version.json        ← номер версии, по нему сайт узнаёт об обновлении
├── logo.png            ← исходник логотипа (квадрат, 1254×1254)
├── icons/              ← иконки сайта, СОБИРАЮТСЯ скриптом
├── make-icons.js       ← собирает иконки из logo.png
├── bump-version.js     ← меняет номер версии везде сразу
│
└── desktop/            ← приложение для компьютера
    ├── main.js         ← окно, скачивание моделей, обновления
    ├── preload.js      ← мостик между окном и системой
    ├── sync-renderer.js← переносит интерфейс с сайта в приложение
    ├── setup-ort.js    ← раскладывает движок нейросети
    ├── setup-transformers.js ← раскладывает библиотеку распознавания
    ├── build/          ← иконки приложения и хук подписи
    └── renderer/
        ├── index.html  ← КОПИЯ с сайта, руками не править
        ├── style.css   ← КОПИЯ с сайта, руками не править
        ├── app.js      ← КОПИЯ с сайта, руками не править
        ├── desktop.js  ← только для приложения: удаление вокала и разметка текста
        ├── align.js    ← подгонка своего текста под песню (выравнивание)
        ├── dsp.js      ← преобразования звука для нейросети
        ├── separator-worker.js ← сам расчёт разделения
        └── whisper-worker.js   ← распознавание текста песни
```

### Главное правило

**`desktop/renderer/index.html`, `style.css` и `app.js` править нельзя.**
Это копии файлов из корня. Правишь в корне, потом переносишь командой:

```bash
npm run app:sync
```

Скрипт сам поменяет что нужно для приложения (политика безопасности,
подключение движка, блок «Убрать вокал нейросетью») и упадёт с понятной
ошибкой, если на сайте что-то переставили так, что переносить некуда.

Свои, не общие с сайтом файлы: `desktop.js`, `align.js`, `dsp.js`,
`separator-worker.js` — их правь прямо в `desktop/renderer/`.

## Первая настройка

### 1. Открыть проект

В WebStorm: **File → Open** → выбрать папку `karaoke-maker`.

### 2. Поставить зависимости приложения

Сайту зависимости не нужны — он работает как есть. А приложению нужны:

```bash
npm run app:install
```

Это поставит Electron и движок нейросети (~400 МБ) и разложит его файлы
в `desktop/renderer/ort/`. В гит они не попадают.

Установщик Electron иногда обрывается на распаковке — молча, без ошибки.
Проект это переживает: после установки автоматически запускается проверка,
которая при необходимости распакует Electron из кэша сама. Если всё же
получишь «Electron failed to install correctly», выполни `npm --prefix desktop run fix`.

### 3. Проверить, что всё запускается

```bash
npm run app:start
```

Должно открыться окно приложения.

### Все команды одним списком

WebStorm показывает их панелью: **вид слева → npm** (или дважды Shift,
набрать «npm»). Запуск двойным кликом, никаких терминалов.

| Команда | Что делает |
|---|---|
| `npm run serve` | локальный сервер сайта на http://localhost:8765 |
| `npm run versions` | показать текущие номера версий |
| `npm run icons` | пересобрать иконки из `logo.png` |
| `npm run app:install` | поставить зависимости приложения |
| `npm run app:sync` | перенести интерфейс с сайта в приложение |
| `npm run app:start` | запустить приложение |
| `npm run app:build:mac` | собрать установщик для macOS |
| `npm run app:build:win` | собрать установщик для Windows |
| `npm run app:build` | собрать оба |

Дальше в инструкции используются именно эти короткие команды —
их можно набрать в терминале из корня проекта или запустить
двойным кликом из панели npm.

## Как менять сайт

### Локальный просмотр

Просто открыть `index.html` файлом **не получится** — браузер запретит
часть возможностей. Нужен локальный сервер.

**В WebStorm:** правый клик по `index.html` → **Open in Browser** →
любой браузер. WebStorm сам поднимет сервер на `localhost:63342`.

**Или командой:**

```bash
python3 -m http.server 8765
```

и открыть http://localhost:8765

### Правишь и смотришь

1. Меняешь `index.html` / `style.css` / `app.js`
2. Обновляешь страницу в браузере
3. Если изменения не видно — **Cmd+Shift+R** (обновление мимо кэша).
   Браузер очень любит показывать старую версию, это нормально.

### Публикация

```bash
node bump-version.js site 1.3.0    # поднять номер версии
git add -A
git commit -m "Что поменял"
git push
```

Через 1–10 минут GitHub Pages пересоберёт сайт. У тех, кто уже открыл
страницу, сверху появится зелёная полоса «Вышла новая версия».

**Зачем поднимать версию.** Номер живёт в трёх местах, и все три
обязательны: в `app.js` (с чем сверяется браузер), в `version.json`
(что лежит на сервере) и в путях `?v=` внутри `index.html` (чтобы
браузер взял свежие css и js, а не старые из кэша). Скрипт
`bump-version.js` меняет все три сразу — руками легко забыть одно
и потом полдня гадать, почему правки «не применяются».

Посмотреть текущие номера: `node bump-version.js` без аргументов.

### Окно «Что нового»

После обновления студия один раз показывает окно со списком изменений.
Тому, кто зашёл впервые (в хранилище браузера пусто), окно не показывается.
Открыть его вручную можно кнопкой в подвале.

`bump-version.js` его **не трогает** — список правится руками, когда есть
о чём рассказать. Три места, и все три обязательны:

1. `index.html`, блок `id="whatsnew"` — заголовок и сами пункты.
   Пункт про то, чего на сайте нет (нейросети), помечается классом
   `only-desktop`; строка «а в приложении ещё…» — классом `only-web`.
   Показ переключает класс `is-desktop` на `body`, его ставит `desktop.js`.
2. `app.js`, константа `NEWS_VERSION` — версия, про которую написан список.
   Она отдельна от `APP_VERSION` нарочно: мелкий выпуск без новостей
   не должен показывать окно со старым списком.
3. `index.html`, подпись кнопки в подвале — там тоже стоит номер.

## Как менять приложение

### Если правишь общий интерфейс

```bash
# 1. Правишь в корне: index.html / style.css / app.js
# 2. Переносишь в приложение
npm run app:sync
# 3. Смотришь
npm run app:start
```

### Если правишь только приложение

Файлы `desktop/renderer/desktop.js`, `dsp.js`, `separator-worker.js`
и `desktop/main.js` — правишь напрямую, `sync` не нужен.

### Быстрая проверка без кликов

```bash
KARAOKE_SELFTEST=1 npm run app:start
```

Приложение откроется, проверит интерфейс, напечатает отчёт и закроется.
Если добавить `KARAOKE_E2E=1`, оно ещё и прогонит настоящее разделение
вокала на 25 секундах звука — занимает около минуты.

Распознавание текста проверяется на настоящей записи:

```bash
# файл речи можно сделать встроенным синтезатором macOS
say -v Milena -o /tmp/s.aiff "Ой мороз, мороз. Не морозь меня."
afconvert -f WAVE -d LEI16@16000 -c 1 /tmp/s.aiff test-speech.wav

KARAOKE_SELFTEST=1 KARAOKE_ASR_E2E=$PWD/test-speech.wav npm run app:start
```

Печатает распознанный текст, число слов с метками и получившиеся строки.
Модель докачается сама. Можно задать `KARAOKE_ASR_LANG=` (пусто — определить
язык самому) и `KARAOKE_ASR_MODEL=small`.

Годится любой файл, который открывает само приложение, — mp3 и m4a в том
числе, переводить в wav не нужно. Синтезатор речи для проверки распознавания
почти бесполезен: беды вылезают только на настоящем пении, так что для
серьёзной проверки берите живую песню.

Ещё переменные:

* `KARAOKE_ASR_SEP=1` — сначала выделить вокал нейросетью и распознавать
  уже его. Это тот путь, ради которого всё задумано: по чистому голосу
  ошибок заметно меньше, чем по полному миксу. Небыстро — разделение
  трёхминутной песни занимает пару минут само по себе.
* `KARAOKE_ASR_DEBUG=1` — печатать разбор по каждому 30-секундному окну:
  что решил сторож зацикливания и переслушивал ли он окно. Нужно, когда
  подбираете пороги в `whisper-worker.js`.

### Проверка подгонки своего текста

Главный способ работы проверяется той же командой, только с файлом
правильного текста:

```bash
KARAOKE_SELFTEST=1 \
  KARAOKE_ASR_E2E=$PWD/песня.mp3 \
  KARAOKE_ASR_ALIGN=$PWD/текст.txt \
  KARAOKE_ASR_SEP=1 \
  KARAOKE_ASR_DUMP=/tmp/слова.json \
  npm run app:start
```

Печатает строку `FIT-E2E` с цифрами, по которым и видно, получилось или
нет. На что смотреть:

* **`доляОпор`** — главная цифра: какая часть слов текста получила
  настоящее время, а не растянута между соседями. На живой песне с
  чистым вокалом это около 0,8.
* **`монотонно`** и **`студияПорядокСтрок`** — времена обязаны строго
  возрастать, ничего не должно налезать друг на друга.
* **`покрытие`** — доля длины песни, на которую легла разметка. Заметно
  меньше единицы бывает честно (песня кончается проигрышем), а вот 0,5
  означает, что разметка сжалась к началу.
* **`самаяДлиннаяРастяжка`** — самый длинный кусок без опор, в секундах.
* **`сомнительныхСтрок`** — сколько строк помечено знаком `≈`.
* **`строки`** и **`опорыПоСтрокам`** — глазами сверить несколько строк
  с тем, где их реально поют.

Две переменные ускоряют работу над самим выравниванием:

* `KARAOKE_ASR_DUMP=<файл>` — сохранить услышанные слова с метками;
* `KARAOKE_ASR_WORDS=<файл>` — взять их оттуда вместо нового прогона
  нейросети. Подгонка тогда считается за секунду, и пороги в `align.js`
  можно подбирать, не слушая песню заново по три минуты.

### Проверка сцены: концы строк и проигрыши

В том же `FIT-E2E` есть раздел **`сцена`** — то, что человек увидит
в караоке и в видео. Считается теми же `lineSpan` и `stagePhase`, что
рисуют настоящую сцену, поэтому цифрам можно верить:

* **`проигрышей`** и **`проигрыши`** — сколько нот `♪ ♪ ♪` и где именно;
* **`паузы`** — все промежутки между строками. По ним видно, каким мог бы
  быть порог `BREAK_MIN` и не жмётся ли он к какой-нибудь настоящей паузе;
* **`строки`** — у каждой `сырое` (что дала подгонка), `старт` (куда
  подтянул голос), `сдвиг`, `конец` и `длина`;
* **`кусковГолоса`** и **`куски`** — что нашла речевая активность
  на вокальной дорожке. Если кусков подозрительно мало, значит пороги
  `VOICE_ON_DB` / `VOICE_OFF_DB` в `app.js` склеили песню в одно пятно.

Ещё две переменные — про вокальную дорожку:

* `KARAOKE_VOICE_DUMP=<файл>` — сохранить огибающую голоса после
  разделения (base64, около 23 КБ на три минуты);
* `KARAOKE_VOICE=<файл>` — подставить её вместо нового разделения.

Вместе с `KARAOKE_ASR_WORDS` это даёт полный прогон сцены за десяток
секунд вместо пяти минут — на живой песне, с настоящим голосом:

```bash
KARAOKE_SELFTEST=1 \
  KARAOKE_ASR_E2E=$PWD/песня.mp3 \
  KARAOKE_ASR_ALIGN=$PWD/текст.txt \
  KARAOKE_ASR_WORDS=/tmp/слова.json \
  KARAOKE_VOICE=/tmp/голос.b64 \
  npm run app:start
```

Огибающую и слова перед этим надо один раз выгрузить настоящим прогоном
с `KARAOKE_ASR_SEP=1`, `KARAOKE_ASR_DUMP=` и `KARAOKE_VOICE_DUMP=`.

## Как выпустить новую версию приложения

Полный цикл, все шаги обязательны.

### 1. Поднять номер

```bash
node bump-version.js app 1.2.0
```

### 2. Собрать установщики

```bash
npm run app:build:mac    # macOS, Apple Silicon → desktop/dist/*.dmg
npm run app:build:win    # Windows x64 и ARM   → desktop/dist/*.exe
npm run app:build        # сразу оба
```

Windows-сборка делается прямо на Маке, ничего доустанавливать не надо.

**Обязательно посмотри вывод сборки.** Там должны быть строки:

```
• подписываем ad-hoc      15 объектов
• подпись проверена       ok
```

Если их нет — сборка для macOS получится «повреждённой» и не запустится.
Причина всегда одна: сломался хук `desktop/build/afterPack.js`.
Проверить, что он на месте:

```bash
grep -c codesign desktop/build/afterPack.js    # должно быть больше нуля
```

### 3. Проверить сборку

```bash
codesign --verify --deep --strict "desktop/dist/mac-arm64/Бэнэнгская Рапсодия.app"
```

Тишина в ответ — значит всё хорошо.

### 4. Выложить релиз

Через сайт GitHub: **Releases → Draft a new release**.

- Тег: `v1.2.0` (обязательно с буквой `v`)
- Приложить оба файла из `desktop/dist/`
- **Переименовать их латиницей** перед загрузкой, например
  `Benengskaya-Rapsodiya-1.2.0-macOS-arm64.dmg`. С кириллицей в имени
  прямые ссылки ломаются на кодировке.

### 5. Обновить ссылки на сайте

В `index.html`, блок «Версия для компьютера» (секция `id="desktop"`) —
заменить в двух ссылках `v1.1.0` и номер в имени файла на новые. Затем:

```bash
node bump-version.js site 1.3.0
npm run app:sync
git add -A && git commit -m "Выпуск 1.2.0" && git push
```

Установленные приложения увидят новую версию сами — они раз в 6 часов
спрашивают GitHub и показывают полосу со ссылкой на скачивание.

## Частые грабли

**«Правки не применяются» на сайте.** Кэш браузера. **Cmd+Shift+R**.
Если и это не помогло — проверь, что поднял версию: `node bump-version.js`.

**«Приложение повреждено» на macOS.** Сборка без подписи. См. шаг 2
выпуска: в логе должно быть «подпись проверена ok».

**Приложение не запускается после скачивания.** Так и должно быть при
первом запуске — оно не заверено у Apple. Лечится один раз:

```bash
xattr -dr com.apple.quarantine "/Applications/Бэнэнгская Рапсодия.app"
```

**Сайт вечно предлагает обновиться.** Разъехались `app.js` и
`version.json`. Проверить: `node bump-version.js` — он предупредит.

**`npm run sync` ругается «не нашёл блок».** На сайте переставили или
переименовали кусок разметки, за который цепляется скрипт. Открой
`desktop/sync-renderer.js` — там в комментариях написано, что он ищет,
и поправь либо разметку, либо скрипт.

**Пропали файлы движка после `git clean`.** Вернуть:
`npm --prefix desktop run setup`

**«Electron failed to install correctly».** Установка Electron оборвалась
на распаковке. Починить: `npm --prefix desktop run fix` — распакует из кэша.
Если и это не помогло, удалить `desktop/node_modules/electron` и повторить
`npm run app:install`.

## Как это устроено внутри

Кратко, чтобы было понятно, куда лезть.

**Сайт** — три файла без сборщика и зависимостей. `app.js` разбит на
разделы комментариями: аудио-движок, шаги студии (песня → текст →
синхронизация → редактор → караоке), оформление, экспорт.

**Приложение** — то же самое в окне Electron плюс удаление вокала
нейросетью Demucs. Расчёт идёт в фоновом потоке окна на WebAssembly:
нативная версия библиотеки внутри Electron падает. Модель (172 МБ)
скачивается при первом использовании и лежит в папке настроек
приложения, а не в репозитории.

**Подгонка своего текста под песню** (`renderer/align.js`) — главный
способ работы со вторым шагом. Идея простая: свободное распознавание
пения врёт в буквах, но время называет довольно точно — слово услышано
там, где его действительно поют, просто записано криво. Значит, буквы
берём у человека, а времена у нейросети.

Технически это выравнивание двух последовательностей слов: что услышала
модель и что вставил пользователь.

1. Оба ряда нормализуются: нижний регистр, ё→е, прочь знаки препинания,
   цифры разворачиваются в слова («4» → «четыре») — иначе отсчёт в песне
   теряет опоры на ровном месте.
2. Выравнивание — Нидлман—Вунш, но сравнение не строгое, а по похожести:
   `1 − расстояние Левенштейна / длина` плюс небольшая надбавка за
   совпавшее начало слова (пение съедает окончания чаще, чем корни).
   Порог `MATCH_MIN = 0,6`: «пабричном» и «фабричном» сцепляются,
   «шагала» и «сжигала» — уже нет.
3. Ходов пять, а не три: кроме «слово ↔ слово» и пропусков есть склейки
   «одно слово ↔ два услышанных» и наоборот — модель то делит распев на
   части, то приклеивает предлог к слову.
4. Текст пользователя выравнивается целиком, а распознанному разрешено
   свободно свисать с обоих концов: болтовня до и после песни ничего
   не стоит.
5. Совпавшие слова получают настоящее время — это **опоры**. Остальные
   раскладываются между соседними опорами пропорционально числу слогов
   (гласных): длинное слово поётся дольше короткого. До первой опоры и
   после последней текст отматывается на столько, сколько нужно этим
   слогам по средней скорости пения в этой же песне.
6. Порядок жёстко возрастающий: метки самой нейросети изредка идут
   вспять, такие опоры выбрасываются.

Строки собираются ровно так, как их разбил человек: перевод строки —
граница строки, пустая строка — разделитель куплетов, в разметку не идёт.
Строка, где опор меньше трети, помечается «сомнительной» — в списке
синхронизации у неё стоит знак `≈`. Пометка снимается, как только
человек поправил метку руками.

Повторяющиеся припевы отдельной обработки не требуют: выравнивание
последовательное и порядок сохраняет, поэтому второй припев цепляется
за второе исполнение. Строки, которых в песне нет (названия куплетов),
просто остаются без опор и разметку не ломают — они получают время в
щели между соседями и помечаются знаком `≈`.

**Свободное распознавание текста песни** — Whisper через transformers.js,
тоже в фоновом потоке. Нужно, когда текста песни нет под рукой; это
черновик, а не готовый результат. Устроено так же: модель качается при первом
использовании в `<папка настроек>/models/` и отдаётся странице по адресу
`app://bundle/models/…` — обработчик схемы в `main.js`. Тонкости, на
которых легко споткнуться:

- нужны сборки **`_timestamped`**: обычные экспортированы без внимания
  декодера к кодировщику, а без него меток по словам не получить;
- `graphOptimizationLevel: 'disabled'` обязателен: оптимизатор свежего
  onnxruntime падает на квантованной сборке Whisper;
- пути к движку задаём поимённо, иначе библиотека просит сборку
  `asyncify` — она нужна только для WebGPU и весит вдвое больше;
- HuggingFace отвечает **относительными** адресами при перенаправлении,
  их надо достраивать, иначе загрузка молча висит;
- прогресс и отмена идут только через `streamer`: старое
  `callback_function` библиотека больше не вызывает, и полоса молча
  замирала на 10% до самого конца. Насколько далеко зашли, видно
  по служебным меткам времени в потоке токенов.

Разделение вокала отдаёт и чистый голос: распознавание слушает его,
а не полный микс — так заметно точнее. И не только распознавание —
на нём же держится вся сцена.

### Где строка кончается и где проигрыш

Раньше конец строки был выдуман: если до следующей строки больше шести
секунд, строка объявлялась спетой ровно за четыре, остальное — проигрыш.
На распеве подсветка обрывалась на полуслове, а коротких проигрышей
набегало столько, что петь было сумбурно: на трёхминутной песне
шестнадцать штук, из них тринадцать короче двух с половиной секунд.

Теперь у сцены есть два настоящих источника: **времена по каждому слову**
(разметка вручную или подгонка текста) и **огибающая громкости чистого
вокала**. Вся арифметика — в `lineSpan` и `stagePhase` в `app.js`, оттуда
её берут и караоке, и предпросмотр редактора, и отрисовка видео. Иначе
записанный ролик разошёлся бы с тем, что человек видел на экране.

**Огибающая голоса.** Держать вокальную дорожку целиком незачем: после
разделения из неё считается среднеквадратичная громкость окном 20 мс
с шагом 10 мс — сто отсчётов в секунду, по байту на отсчёт. Громкость
пересчитывается в децибелы от 95-го процентиля дорожки (не от максимума:
на процентиль не влияют ни редкие всплески, ни длинные куски тишины),
и байта хватает на шестьдесят децибел. Три минуты песни — семнадцать
килобайт, они лежат в проекте вместе с текстом и переживают перезагрузку.

Где голос звучит, определяется двумя порогами, а не одним, — иначе на
границе дребезжит: голос «включается» на −25 дБ и «выключается», только
упав ниже −35 дБ. Куски короче 0,18 с выбрасываются, паузы короче 0,3 с
склеиваются — это вдохи между словами, а не тишина.

**Конец строки** берётся, в порядке важности: конец, выставленный руками
в редакторе (`line.ручнойКонец`); конец последнего слова; следующая
строка, если она идёт сразу; и только когда не известно ничего — средняя
длина строки в этой же песне. Поверх всего: если в этот момент голос ещё
звучит, строка тянется до конца пения, но не больше чем на четыре секунды
и не дальше следующей строки. Хвост достаётся последнему слову — на
распеве тянется именно оно, а не вся строка разом.

Важная тонкость: конец, пришедший от распознавания, — это всего лишь
конец последнего слова, и продлевать его голосом не только можно, но
и нужно. Поэтому «ручной конец» помечается отдельно, а не угадывается
по тому, что поле `end` заполнено.

**Начало строки** подтягивается к ближайшему вступлению голоса в узком
окне: ±0,7 с, а для строки со знаком `≈` (подгонка сама призналась, что
время подобрано на глазок) ±1,5 с. Окно вдобавок не шире половины
расстояния до соседей — иначе две строки подтянулись бы к одному
вступлению и налезли друг на друга. Метки слов едут за строкой ровно на
ту же величину, и только если сдвинутая строка налезает на следующую,
она ужимается.

**Проигрыш** ставится, только если между концом строки и вступлением
следующей голоса нет **восьми секунд и дольше**. Порог выбран по живой
песне: там паузы между строками — от 0,02 до 2,3 с, а настоящих
инструментальных кусков два, 16 и 30 секунд. Между 2,3 и 16 секундами
на этой песне нет ничего, так что любой порог от 3 до 15 даёт один и тот
же ответ; восемь секунд стоят посреди этого пустого места и совпадают
с тем, что принято в нынешних караоке. Настройкой порог не сделан
намеренно: ручка, которую нечем осмысленно крутить, только мешает.

Короткие паузы не отмечаются нотами — о вступлении следующей строки
предупреждает отсчёт из трёх точек (`COUNT_LEAD`, `COUNT_MIN_GAP`),
а сама строка стоит допетой. Это то, как ведут себя нынешние караоке.

**Без вокальной дорожки** — на сайте всегда, в приложении пока не убран
вокал нейросетью — работает ровно то же самое, только без подтяжки
к голосу и без хвоста распева: конец строки берётся из времён слов,
а где нет и их — из средней длины строки в песне. Ничего не падает,
проигрышей всё равно становится сильно меньше прежнего.
