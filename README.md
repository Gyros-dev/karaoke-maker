# Karaoke Punch

Караоке-студия: загрузить песню, убрать вокал, разметить текст, спеть
и сохранить видео. Работает в браузере и отдельным приложением
для компьютера.

- **Сайт:** https://gyros-dev.github.io/karaoke-maker/
- **Приложение:** https://github.com/Gyros-dev/karaoke-maker/releases

Ниже — инструкция, как всё это чинить и обновлять самому.
Написана под WebStorm, но команды обычные, подойдёт любой редактор.

### Главное правило

**`desktop/renderer/index.html`, `style.css`, `app.js`, `i18n.js`,
`pitch-worker.js`, `tempo.js` и `fft.js` править нельзя.**
Это копии файлов из корня. Правишь в корне, потом переносишь командой:

```bash
npm run app:sync
```

Скрипт сам поменяет что нужно для приложения (политика безопасности,
подключение движка, блок «Убрать вокал нейросетью») и упадёт с понятной
ошибкой, если на сайте что-то переставили так, что переносить некуда.

Свои, не общие с сайтом файлы: `desktop.js`, `align.js`, `dsp.js`,
`separator-worker.js` — их правь прямо в `desktop/renderer/`.

## Первая настройка

### 1. Открыть проект

В WebStorm: **File → Open** → выбрать папку `karaoke-maker`.

### 2. Поставить зависимости приложения

Сайту зависимости не нужны — он работает как есть. А приложению нужны:

```bash
npm run app:install
```

Это поставит Electron и движок нейросети (~400 МБ) и разложит его файлы
в `desktop/renderer/ort/`. В гит они не попадают.

Установщик Electron иногда обрывается на распаковке — молча, без ошибки.
Проект это переживает: после установки автоматически запускается проверка,
которая при необходимости распакует Electron из кэша сама. Если всё же
получишь «Electron failed to install correctly», выполни `npm --prefix desktop run fix`.

### 3. Проверить, что всё запускается

```bash
npm run app:start
```

Должно открыться окно приложения.

### Все команды одним списком

WebStorm показывает их панелью: **вид слева → npm** (или дважды Shift,
набрать «npm»). Запуск двойным кликом, никаких терминалов.

| Команда | Что делает |
|---|---|
| `npm run serve` | локальный сервер сайта на http://localhost:8765 |
| `npm run versions` | показать текущие номера версий |
| `npm run icons` | пересобрать иконки из `logo.png` |
| `npm run app:install` | поставить зависимости приложения |
| `npm run app:sync` | перенести интерфейс с сайта в приложение |
| `npm run app:start` | запустить приложение |
| `npm run app:build:mac` | собрать установщик для macOS |
| `npm run app:build:win` | собрать установщик для Windows |
| `npm run app:build` | собрать оба |

Дальше в инструкции используются именно эти короткие команды —
их можно набрать в терминале из корня проекта или запустить
двойным кликом из панели npm.

## Как менять сайт

### Локальный просмотр

Просто открыть `index.html` файлом **не получится** — браузер запретит
часть возможностей. Нужен локальный сервер.

**В WebStorm:** правый клик по `index.html` → **Open in Browser** →
любой браузер. WebStorm сам поднимет сервер на `localhost:63342`.

**Или командой:**

```bash
python3 -m http.server 8765
```

и открыть http://localhost:8765

### Правишь и смотришь

1. Меняешь `index.html` / `style.css` / `app.js`
2. Обновляешь страницу в браузере
3. Если изменения не видно — **Cmd+Shift+R** (обновление мимо кэша).
   Браузер очень любит показывать старую версию, это нормально.

### Публикация

```bash
node bump-version.js site 1.3.0    # поднять номер версии
git add -A
git commit -m "Что поменял"
git push
```

Через 1–10 минут GitHub Pages пересоберёт сайт. У тех, кто уже открыл
страницу, сверху появится зелёная полоса «Вышла новая версия».

**Зачем поднимать версию.** Номер живёт в четырёх местах, и все четыре
обязательны: в `app.js` (с чем сверяется браузер), в `version.json`
(что лежит на сервере), в путях `?v=` внутри `index.html` (чтобы
браузер взял свежие css и js, а не старые из кэша) и в корневом
`package.json` — это пакет **сайта** (`karaoke-punch-site`), пакет
приложения лежит отдельно, в `desktop/package.json`. Скрипт
`bump-version.js` меняет все четыре сразу — руками легко забыть одно
и потом полдня гадать, почему правки «не применяются».

Корневой `package.json` наружу не выходит (`private: true`), и раньше
его номер не двигал никто: он отстал до `1.2.0`, когда везде было уже
`1.12.0`, и читался как ошибка. Теперь его двигает `bump-version.js`
вместе с остальными, а запуск без аргументов предупреждает, если он
опять отстал.

Посмотреть текущие номера: `node bump-version.js` без аргументов.

### Окно «Что нового»

После обновления студия один раз показывает окно со списком изменений.
Тому, кто зашёл впервые (в хранилище браузера пусто), окно не показывается.
Открыть его вручную можно кнопкой в подвале.

`bump-version.js` его **не трогает** — список правится руками, когда есть
о чём рассказать. Два места:

1. `index.html`, блок `id="whatsnew"` — сами пункты.
   Пункт про то, чего на сайте нет (нейросети), помечается классом
   `only-desktop`; строка «а в приложении ещё…» — классом `only-web`.
   Показ переключает класс `is-desktop` на `body`, его ставит `desktop.js`.
2. `index.html`, атрибут `data-news-version` у `<html>` — версия, про
   которую написан список. Она отдельна от `APP_VERSION` нарочно: мелкий
   выпуск без новостей не должен показывать окно со старым списком.

Больше номер нигде не повторяется. Отсюда его берёт `app.js`
(`NEWS_VERSION`) и `i18n.js` — тот подставляет его вместо `{версия}`
в заголовок окна и в подпись кнопки подвала, одинаково на обоих языках.
В словаре перевода номера нет: там он однажды отстал, и по-английски
окно объявляло прошлую версию.

### Перевод интерфейса

Языка два: русский и английский. Русский — исходный, английский — перевод.
Выбор живёт в `localStorage` под ключом `karaoke-lang`, и вместе с ним
меняется `lang` у `<html>`. При первом заходе язык всегда русский:
настройки браузера не спрашиваем, английский — только по явному выбору.
Переключатель один, в шапке; она липкая и видна с любого шага студии.

Весь словарь — в `i18n.js`, двумя таблицами, потому что у надписей два
происхождения:

* **`I18N.EN`** — то, что написано прямо в `index.html`. Русский остаётся
  в разметке, элемент помечается ключом, а здесь лежит только английский:
  ```html
  <button data-i18n="шаг1.выбрать">Выбрать</button>
  <input data-i18n-placeholder="шаг2.поле" placeholder="Вставь сюда…">
  ```
  Русский снимается с документа при первом применении, поэтому правка
  разметки не может разойтись с переводом — менять надо одно место.
  Есть `data-i18n` (текст), `data-i18n-html` (для абзацев с `<b>`, `<a>`
  и `<span class="mod-key">` внутри) и `data-i18n-title`, `-placeholder`,
  `-aria`, `-alt`, `-content`, `-mod-title` для атрибутов.

* **`I18N.СТРОКИ`** — то, что собирается в коде: сообщения, подписи,
  которые ставит JS, оценки времени. Брать русский из документа неоткуда,
  поэтому лежат обе стороны: `{ ru: '…', en: '…' }`. В коде — через `t()`:
  ```js
  alert(t('песня.неПрочиталась'));
  el.textContent = t('ред.размечено', { n: 5, 'всего': 12 });
  ```
  Подстановки пишутся `{имя}`, склонения считает `Intl.PluralRules`:
  значение может быть не строкой, а набором форм (`one`/`few`/`many`/`other`)
  — у русского и английского они разные.

Что **не** переводится: текст песни, имена файлов, названия моделей —
это данные человека.

Фоновые потоки (`separator-worker.js`, `whisper-worker.js`) живут отдельными
файлами и про выбранный язык не знают, поэтому шлют не готовую строку,
а `ключ` и `парам`; складывает надпись `desktop.js`. Меню приложения
собирается в главном процессе, и о языке он узнаёт от страницы через
`window.desktop.setLanguage()`.

Добавляешь надпись — добавь ключ, иначе на английском останется русский
текст. Полноту проверяет самопроверка приложения, раздел `язык`:
переключает язык туда-обратно и требует, чтобы при английском в ключевых
местах не было кириллицы, при русском она была везде, а совпадающих
надписей между языками не осталось вовсе.

### Словарь терминов

Одна вещь — одно имя, и в русском, и в английском. Это не про красоту:
человек читает «дорожка» в одном месте и «полоса» в другом и не понимает,
одно это или разное. Пишешь новую надпись — бери слово отсюда, а не
придумывай синоним.

Как выбирали, когда слов оказывалось два: **побеждает то, что уже стоит
в самом заметном месте** — в названии шага, в заголовке окна, на кнопке;
его человек видит чаще всего. Если у понятия есть общепринятое имя
в монтажных программах, берём его.

Жирным помечено то, что раньше двоилось. Коротко, почему выбрано так:

* **дорожка / полоса.** Дорожка — вся монтажная дорожка целиком: так она
  названа в подсказке шага 3 и в заголовке блока руководства. Полоса —
  один её ряд: так подписана колонка заголовков и так сказано в справке
  редактора («верхняя полоса — оригинал»). По-английски ряд — `track`,
  как в Logic Pro и Premiere, а `lane` из Final Cut убрано.
* **песня, а не трек.** Первый шаг называется «Песня», заголовок сайта —
  «Преврати любую песню в караоке». `Track` в английском освободилось
  под ряд дорожки.
* **оформление, а не `styling`.** `Look` — название закладки на четвёртом
  шаге, это самое заметное место; `styling` жило только в подсказках.
* **просмотр, а не просмотр.** «Просмотр» — заголовок среднего окна
  редактора, а заголовок окна весомее подсказки.
* **разметка, а не синхронизация.** Отдельного шага «Синхронизация» нет
  с версии 1.9; слово осталось в двух сообщениях и убрано.
* **проект и черновик.** Проект — всё, что студия помнит о песне;
  черновик — тот же проект, но сохранённый файлом. «Работа» как третье
  имя того же убрана.
* **отрезок и диапазон.** Отрезок — только про оригинал; выделенные
  строки — диапазон (`range`), чтобы английское `stretch` значило
  одно.
* **стык слов — `joint`,** не `handle`: ручка (`handle`) есть у каждого
  края, а стык один на два слова.
* **подложка — `scrim`,** не «полоса» и не `band`: «полоса» занята рядом
  дорожки.
* **тема, а не «тема оформления»:** иначе «оформление» значило бы сразу
  и вид текста, и гамму студии.

Что **не** разведено намеренно: «край» и «граница» в русском ходят
парой. Развести их можно только переписав целые абзацы, а вреда от них
нет — читаются они как одно и то же, чем и являются.

Не термины и не переводятся: текст песни, имена файлов, названия
моделей и чужих программ (UVR5, Whisper, Logic Pro).

### Тема

Три темы, все устроены как язык — атрибут на `<html>` (`data-theme`),
ключ в `localStorage` (`karaoke-theme`), переключатель собирается кодом
и стоит в шапке рядом с языковым (`app.js`, раздел «Переключение темы»,
и `THEME` в `window`). Тема не зависит от языка и не трогает остальной
сайт — только `.studio` (все четыре шага студии).

* **«Фирменная» (`signature`)** — по умолчанию. Прежний синевато-чёрный
  грунт, зелёный — ровно в четырёх местах: кнопка воспроизведения,
  включённый переключатель (например, магнит), выделенный блок
  (в списке строк и на дорожке), цифры счётчика.
* **«Нейтральная» (`neutral`)** — серый грунт без оттенка, вместо
  зелёного жёлтая рамка выделения. Заметно, что выбрано, а не что
  за бренд у студии.
* **«Стальная» (`steel`)** — холодный серо-стальной грунт, панели
  **светлее** фона (в двух других темах наоборот), синий акцент вместо
  зелёного и колонка заголовков полос темнее рабочего поля дорожки.
  Манера больших монтажных программ: студия рядом с Logic Pro должна
  читаться как инструмент того же класса. Канвас при этом остаётся
  тёмным нарочно — волна, блоки строк и слова нарисованы светлыми
  полупрозрачными красками, и на светлом поле от них не осталось бы
  ничего.

Переменные всех трёх лежат в `style.css`: `.studio { --sel-ring: …; }`
задаёт фирменную (переопределять общие `--bg-card`/`--border`/`--text`
не приходится — они уже совпадают с фирменным грунтом), а
`html[data-theme="neutral"] .studio { … }` и
`html[data-theme="steel"] .studio { … }` переопределяют их для двух
остальных. У стальной сверх того перекрашены адресно четыре места, где
зелёный написан прямо цветом, а не переменной, и переменной там взяться
неоткуда: главная кнопка шага, подсветка активного шага, его точка и
текущая строка в списке. Канвас дорожки CSS не читает, поэтому его
цвета (грунт, рамка выделения, её свечение) кэшируются в `app.js`
в объекте `edTheme` и обновляются только при смене темы —
`getComputedStyle` на каждый кадр отрисовки был бы не по карману.

**Переключатель — выпадающий список.** Три кнопки подряд в шапке
перевешивали бы всё остальное, поэтому там одна кнопка со значком
нынешней темы и уголком, а по нажатию — список из трёх с названиями
и галкой у выбранной. Значки: палитра — фирменная, наполовину залитый
круг — нейтральная, два фейдера — стальная (`ЗНАЧОК_ТЕМЫ` в `app.js`).
Работает с клавиатуры как обычное меню: `Enter`, пробел или `↓` на
кнопке открывают список и ставят фокус на выбранную тему, `↑` и `↓`
ходят по пунктам по кругу, `Enter` выбирает, `Esc` закрывает и
возвращает фокус на кнопку; щелчок мимо тоже закрывает. Подсказки есть
и у кнопки («Тема студии: Стальная. Нажми, чтобы выбрать другую»),
и у каждого пункта, на обоих языках. Языковой переключатель рядом
остаётся парой кнопок: языков два, и обойма для них короче любого
списка.

Самопроверка приложения (раздел `тема`) проверяет не число кнопок
(раньше оно и проверялось — «`кнопокВПереключателе: 2`», от нового
устройства такой счёт не сказал бы ничего), а то, ради чего
переключатель стоит: что он собран списком (одна кнопка, три пункта
с непустыми названиями, отметка у нынешней темы); что список
открывается нажатием, закрывается по `Esc` и по щелчку мимо, а стрелка
ведёт по пунктам; что **выбор пунктом применяется** — меняет атрибут
на `<html>` и переживает перезагрузку (ключ в хранилище), а значок
на кнопке идёт за темой; и что у всех трёх тем **разные цвета**,
причём в двух местах сразу — и рамка выделения (CSS), и грунт канваса
дорожки (`edTheme`, где цвета кэширует код и однажды отставали).

### Значки вместо эмодзи

В оболочке (шапка, панели студии, дорожка, кнопки редактора и караоке)
эмодзи не используются вовсе: у них разный рисунок на macOS и Windows —
разная ширина и высота строки, это было видно на снимках приложения.
Вместо них один спрайт SVG в `index.html` (`<svg class="icon-sprite hidden">`,
скрыт из потока) — набор `<symbol id="i-имя">`, кнопки достают нужный
через `<use href="#i-имя">`. Один цвет (`currentColor`, наследуется
от текста кнопки), один размер (`1em`, растёт вместе с шрифтом).
Внешних библиотек и адресов нет и быть не может — политика безопасности
страницы это и не разрешила бы (`default-src 'self'`).

Значки, которые ставит код (а не разметка), собирает `значокSVG(имя)`
в `app.js` — та же функция доступна и `desktop.js` (значки исполнения
нейросети), потому что оба файла — обычные скрипты в одном окне,
а не модули. Кнопка играть/пауза несёт оба значка сразу, виден только
нужный (класс `.playing`, см. `setPlayIcon`) — раньше подмена шла через
`textContent`, а он стирал бы вложенные `<svg>`.

Там, где эмодзи — содержимое, а не оболочка (например, `♪ ♪ ♪ ♪ ♪` —
значок проигрыша на сцене караоке, `BREAK_TEXT` в `app.js`), он остаётся
как есть: это часть песни, а не элемент управления. Так же не тронуты
эмодзи на витринной части сайта (карточки возможностей, окно «Что
нового», кнопки скачивания) — они не часть студии.

### Свои подсказки у кнопок

Половина кнопок студии — только со значком: черновик, отмена и повтор,
кольцо, магнит, слышимая перемотка, сетка долей, масштаб, «вся песня»,
соло у полос, «на весь экран» в караоке. Объяснение у них было —
в `title`, — но системная подсказка всплывает через секунду, набрана
чужим шрифтом и встаёт не там, где её ждут: до неё просто не дожидались
(«навёл на „сохранить черновик“ — подсказки нет»).

Теперь подсказку рисует сама студия — `ПОДСКАЗКА` в `app.js` и `.tip`
в `style.css`. Работает она **внутри `#studio`**: витрина сайта — обычная
страница, там системная подсказка на месте. Текст берётся из того же
`title`, что уже стоит в разметке, — значит, переводится сам собой через
`data-i18n-title`, и второго списка надписей заводить не надо. Появляется
за 180 мс, встаёт под кнопкой (не помещается — над ней) и держится внутри
окна: у правой кнопки она иначе уезжала бы за край.

Два места, где это устроено не самым очевидным образом.

* Пока указатель на кнопке, `title` с неё **снят** и лежит в `data-tip`:
  иначе поверх своей подсказки через секунду вылезала бы системная.
  Уходит указатель — атрибут возвращается, но только если за это время
  его не переписал код: соло, «развернуть» и кнопки сдвига меняют свою
  подсказку прямо по щелчку. Щелчок гасит подсказку в фазе перехвата,
  до обработчиков кнопки, — по той же причине.
* Прокрутка подсказку **не гасит, а ведёт за кнопкой**. Обычный приём —
  гасить — здесь не годится, и причины две.

  Первая была технической и с тех пор ушла: список строк прокручивался
  к текущей строке едва ли не на каждом кадре, и подсказка не доживала
  бы до своих 180 мс. Это оказалось лишней работой, её убрали (см.
  «Что делается на каждом кадре редактора» ниже): прокрутка теперь идёт
  ровно на смене строки, считанные разы за песню.

  Вторая осталась и она главная: гасить **нечего**. Ни одна кнопка
  с подсказкой не лежит внутри списка строк — соло и уровни стоят
  в колонке заголовков полос, масштаб и магнит на панели, кнопки
  строки в инспекторе. Сетка прокрутилась — эти кнопки не сдвинулись
  ни на пиксель, и гасить над ними подсказку значило бы гасить её
  из-за движения в другом углу экрана. Там же, где кнопка от прокрутки
  правда едет (инспектор прокручивается внутри себя), подсказка едет
  вместе с ней — то есть остаётся на кнопке, а это и требовалось.

Заодно проведена ревизия: у **каждой** кнопки внутри `#studio` есть
внятная подсказка на обоих языках — у шагов, у выбора минусовки и фона,
у закладок и переключателей оформления, у кнопок экспорта и у обеих
кнопок нейросети. Стережёт это раздел самопроверки `подсказки`: он
обходит живую страницу, требует непустую подсказку у всех семи десятков
кнопок и требует, чтобы русская и английская **различались** — забытый
ключ в словаре виден только так.

## Как менять приложение

### Если правишь общий интерфейс

```bash
# 1. Правишь в корне: index.html / style.css / app.js
# 2. Переносишь в приложение
npm run app:sync
# 3. Смотришь
npm run app:start
```

### Если правишь только приложение

Файлы `desktop/renderer/desktop.js`, `dsp.js`, `separator-worker.js`
и `desktop/main.js` — правишь напрямую, `sync` не нужен.

### Окно приложения

Открывается **развёрнутым во весь рабочий стол** (`createWindow`
в `desktop/main.js`). Студия — рабочее место: все четыре шага делят
между собой высоту окна, и на прежнем окне в 1180×900 редактор жил
в тесноте при пустом мониторе вокруг.

Это обычное развёрнутое окно, а **не** полноэкранный режим macOS: тот
прячет системную строку, уводит приложение на отдельный рабочий стол
и выходить из него надо руками. Размер всё равно задаётся числами — по
рабочей области экрана (`screen.getPrimaryDisplay().workAreaSize`):
`maximize()` у ещё не показанного окна на Windows отрабатывает не
всегда, и тогда окно остаётся во весь экран размером, а не крошечным.
`minWidth` / `minHeight` прежние — 900×640.

### Витрины в приложении нет

Приложение показывало всю рекламную часть сайта: шапочное меню
(«Возможности / Как это работает / Вопросы»), кнопку «Открыть студию»,
геройский экран «Преврати любую песню в караоке», карточки возможностей,
частые вопросы и подвал. Человек прочитал это ровно один раз — когда
скачивал программу; при каждом следующем запуске он получал страницу,
которую надо прокрутить, чтобы добраться до рабочего места.

Теперь **в приложении витрины нет вовсе**, а студия занимает окно
целиком: без полей, без скруглений и без прокрутки страницы. Прячет её
CSS по классу `is-desktop` на `body` (его ставит `desktop.js`), а не
скрипт: сайт и приложение — одна и та же страница, и то, что решается
стилями, скриптом решать незачем. Заголовок «Студия» над рядом шагов
там же снят — окно приложения и так подписано. **На сайте всё остаётся
как было:** там витрина продаёт продукт.

Два места, где это не сводится к `display: none`.

* **«Как пользоваться»** в ряду шагов ведёт на раздел `#how` — спрятанный
  раздел означал бы кнопку, которая никуда не ведёт. В приложении ссылка
  открывает тот же самый раздел **окном поверх студии**, как окно «Что
  нового» (`открытьРуководство` в `app.js`, `body.guide-open`
  в `style.css`); закрывают крестиком или `Esc`. Раздел один и тот же —
  второй копии текста не заводится. На сайте это по-прежнему обычная
  ссылка на якорь, и проверяется это в момент щелчка, а не при загрузке:
  класс `is-desktop` ставит `desktop.js`, а он подключается ПОСЛЕ
  `app.js`. Пока окно открыто, клавиши редактора под ним молчат
  (`окноПоверхСтудии`, см. «Клавиши» ниже): раньше человек читал справку
  и молча портил разметку стрелками.
* **«Что нового»** жила кнопкой в подвале, а подвала в приложении больше
  нет. `desktop.js` переносит её в шапку, к переключателям языка и темы:
  оттуда она видна с любого шага и высоты у рабочего места не отнимает.
  Заодно он заново меряет высоту шапки (`measureHeader`): от неё
  считается высота студии, а состав шапки в приложении другой.

Стережёт всё это раздел самопроверки `витрина`: витрины не видно,
заголовок снят, студия ровно во всё окно под шапкой, прокрутки страницы
нет, «Что нового» в шапке и видна, а «Как пользоваться» открывает
руководство и `Esc` его закрывает.

### Быстрая проверка без кликов

```bash
KARAOKE_SELFTEST=1 npm run app:start
```

Приложение откроется, проверит интерфейс, напечатает отчёт и закроется.
В отчёте, кроме прочего, есть `шаговВсего` (их четыре), `редактор` —
дорожка, отмена и магнит, и `простукивание` — режим внутри
редактора: он гоняется пробелом через общий обработчик и проверяет
и то, что режим забирает экран себе, и все правила переписывания меток
(вход ничего не стирает, ранние и недошедшие метки целы, удар
отменяется по отдельности, заход снимается целиком через `Cmd+Z`).
Рядом с ним — `простукиваниеВспять`, у которого свой раздел нарочно:
в `простукивание` заход всегда кончается там, где следующая метка позже
последней простуканной, — ветка «дальше метки идут вспять, стереть их?»
не задевается ни разу. В ней спокойно жило падение (локальная переменная
звалась `t`, той же буквой, что функция перевода, и перекрывала её:
`confirm` валился с «t is not a function» и уносил с собой весь
`finishTapMode`, не дойдя до сохранения, — весь заход пропадал после
перезагрузки). Теперь заход делается дважды, с ответами «нет» и «да»:
вопрос задан ровно один раз и текст его собрался переводом, исключения
не было, «нет» оставляет чужие метки целыми, «да» стирает их с той
строки и дальше, и в обоих случаях простуканное лежит в `localStorage`.

Рядом — `правкаСлов` (выбор слова, поля, клавиши, магнит, кольцо),
`времяВПолях` (время показано минутами, а набрать можно и минутами,
и секундами; буквы и минус отклоняются, не трогая разметку),
`новыеСтроки` (дописанной строке нашлось место между соседями, а
не простуканную никто не выдумывал), `черновик` (круг «собрали →
потеряли → открыли», и чип памяти показывает ту же песню), `соло`
(усиления «только оригинал / только минус / только голос» и то, что
соло не переживает уход из редактора), `уровниДорожек` (числа смеси
и связка ползунка с галкой «слышу оригинал») и `паузаМеждуСловами`
(стык по-прежнему сваривается, с модификатором края расходятся, ручки
ловятся по отдельности, заливка в паузе стоит, в LRC есть метка) и
`клавишиПодОкном` (под каждым из трёх устройств окон — руководство,
«Что нового», окно ожидания — жмётся весь набор клавиш редактора,
и снимок сверяется ПОСЛЕ КАЖДОЙ клавиши, иначе `←` гасила бы `→`;
следом те же клавиши без окна обязаны работать, иначе «ничего не
поменялось» доказывало бы только сломанный обработчик), `стёртаяСтрока`
(пустое поле не принимается, прежний текст возвращается по уходу,
строк не убавляется), `сбросСлов` (дорожка перерисовывается на сбросе
и не меняется от лишней отрисовки — меряется отпечатком пикселей
холста), `длинноеСлово` (слово в триста знаков без пробелов не вылезает
за коробку строки и раскладывается на ряды, а строка с пробелами
и короткая ведут себя как раньше) и
`подсказки` (у каждой кнопки студии есть непустая подсказка, русская
и английская различаются, своя всплывашка встаёт вместо системной и
возвращает `title` на место, а развёрнутая справка стоит после дорожки
и не выходит за низ подложки студии). Про рабочее место — ещё шесть:
`витрина` (в приложении её не видно, студия во всё окно, «Как
пользоваться» открывает руководство), `поискСтрок` (фильтр по
подстроке не перенумеровывает песню и не ломает выбор, клавиши,
прокрутку и правку текста), `инспектор` (свёрнутое вдвое ниже
развёрнутого и переживает перезагрузку), `тема` (переключатель собран
списком, открывается и закрывается, выбор применяется и переживает
перезагрузку, у трёх тем разные цвета — и в CSS, и в кэше канваса),
`ползунокУровня` (наши стили ползунка ДЕЙСТВИТЕЛЬНО выиграли каскад
на живой странице, а не просто лежат в файле) и `высотаДорожки`
(на подставленных эмуляцией 1440×900 и 1280×800 дорожка выросла,
полосы поделили высоту без щели, все четыре шага влезли в подложку)
вместе с `разделителем` (граница окон и дорожки тянется мышью и
стрелками, доля запоминается, окна не съедаются целиком). Про сцену — `подложкаИОтсчёт`:
подложка накрывает обе строки при разведённых ползунках, точки отсчёта
не пересекаются ни с одной строкой, пять нот проигрыша влезают и в узкий
кадр одним рядом, сцена и кадр видео считают подложку одинаково, ползунок
её высоты живёт в проекте, а слышимая перемотка выключена по умолчанию —
и всё это числами, по прямоугольникам, а не на глаз.

Про звук, кроме самой смеси, — `тональность`: длина после сдвига совпадает
отсчёт в отсчёт у обеих дорожек, синус 220 Гц на октаву вверх читается как
440, вниз — как 110, на ±2 полутона — как 246,9 и 196,0 (частота меряется
автокорреляцией, как темп), чистая середина остаётся чистой серединой
(сторона ниже −60 дБ — доказательство, что каналы правятся одинаково),
корреляция каналов не уезжает больше чем на 0,05, тишина остаётся тишиной,
ноль полутонов возвращает ТОТ ЖЕ САМЫЙ буфер, а второй запрос той же
тональности берётся из кэша и не считает заново. Рядом —
`тональностьВСтудии`: то же, но со стороны человека. Минусовка `.wav`
и звук видео и правда звучат в выбранной тональности (минусовка
записана на 330 Гц, после «+2» из обеих выгрузок читается 370,41,
а не 330); отмена на середине счёта возвращает прежние буферы, прежнее
число полутонов и снимает признак занятости, ничего не оставив в кэше;
место в песне после смены не уезжает дальше сотых долей секунды —
играло, значит играет; тональность переживает проект и черновик числом
и при открытии НЕ считается вовсе, а досчитывается на шаге «Караоке»
(и только та, что пришла из памяти, — выбранное стрелками сам никто
не считает); зато черновик с нулевой тональностью поверх звучащей
ненулевой возвращает звук в ноль СРАЗУ, не считая ничего и не показывая
окна ожидания; а подмена минусовки нейросетью обнуляет и кэш, и выбор.

#### Разделы друг другу не мешают

Все полсотни разделов идут подряд по ОДНОМУ окну, над одним состоянием
студии. Раньше уборку за собой делал каждый сам: у одних был `finally`,
у других нет, и ничто не мешало следующему автору забыть. Забыл — и
соседний раздел мерил чужой мусор. На этом спотыкались не раз: `соло`
оставлял открытым караоке, и `простукивание` находило его панель
управления видимой.

Хуже того, мусор переживал ЗАПУСК. Правка разметки сама сохраняет
черновик в `localStorage`, а возврат поля текста черновик НЕ убирает —
`собратьПроект` нарочно бережёт прежний текст, когда поле пустое.
Шесть разделов оставляли там свою «песню», и второй прогон на той же
папке профиля поднимался «с песней»: кнопка читалась как «Подогнать
мой текст» вместо «Распознать текст», и раздел `язык` краснел на ровном
месте. Правило «отдельная папка профиля» это прятало, а признак,
который врёт через раз, приучает не верить красному — самая дорогая
беда, какая тут бывает.

Теперь изоляция не зависит от дисциплины автора. Каждый раздел обёрнут
в `__раздел('имя', () => { … })`: обёртка снимает снимок общего
состояния ДО раздела и возвращает его ПОСЛЕ — что бы раздел ни делал
и чем бы ни кончил. Возвращается всё сразу:

* `localStorage` целиком (ключи, которых не было, удаляются, — в первую
  очередь `karaoke-project`, `karaoke-lang`, `karaoke-theme`);
* поле текста песни — вместе с событием `input`, иначе подпись главной
  кнопки разметки осталась бы от чужого текста;
* активные панели и вкладки шагов, доступность вкладок по `maxStep`,
  классы `<body>` и `<html>`, окна поверх студии;
* `state`, `editor`, `audio`, `voice`, `тон`, `скраб` — поля и один
  уровень вглубь, чтобы правка вида `editor.mix.orig = 0` не пережила
  раздел;
* язык и тема;
* `window.confirm` / `alert` / `prompt` — их подменяют, чтобы обойтись
  без диалогов;
* заход простукивания и разметка слов, если раздел их открыл, —
  закрываются тем же путём, каким закрывает студия.

Кэши отрисовки (`editor.peaks`, `spans`, `stageKey`, `stageDrawn`,
`кадрПоказан`) — единственное, что не возвращается, а ГАСИТСЯ: вернуть
им прежнее значение значило бы соврать редактору, что на холсте лежит
картинка, которой там давно нет.

Огибающая голоса и звуковые буферы не копируются вовсе: это мегабайты
на каждый раздел. Разделы и так подставляют свои, а не правят чужие
изнутри. Цена всей обёртки — в пределах погрешности: проверка как шла
одиннадцать секунд, так и идёт.

**Что обязан автор нового раздела:** только проверять своё и вернуть
`вНорме`. Возвращать состояние руками больше НЕ обязан — ни черновик
в `localStorage`, ни поле текста, ни открытый шаг, ни язык, ни тему.
Свой `finally` полезен там, где раздел сверяет что-то ПОСЛЕ возврата
(так делает `тональностьВСтудии`), но забыть его больше не смертельно.

Исключение внутри раздела тоже больше не уносит всю проверку: обёртка
ловит его и отдаёт `вНорме: false` рядом с `разделСорвался` и текстом
сбоя, а счёт настоящих ошибок страницы (`ошибок`) не трогает — остальные
разделы досчитываются как ни в чём не бывало.

Проверено разделом-вредителем, который нарочно писал чужой черновик,
оставлял открытым чужой шаг и менял язык: без обёртки за ним краснели
`язык` и `подложкаИОтсчёт`, с обёрткой — ни одного `вНорме: false`.

Оговорка про `--lang`: ключ `--lang=en-US` на язык студии НЕ влияет.
`i18n.js` читает язык из `localStorage` (`karaoke-lang`) и по умолчанию
всегда берёт русский — настройки системы он не спрашивает нарочно.
Английский в проверке всё равно покрыт: разделы `язык` и `подсказки`
переключают его сами и сверяют надписи на обоих языках.

Если добавить `KARAOKE_E2E=1`, оно ещё и прогонит настоящее разделение
вокала на 25 секундах звука — тем режимом, который выбран в интерфейсе,
то есть одним проходом: около 36 секунд. `KARAOKE_E2E=быстро` задаёт
один проход явно, минуя выпадающий список, — так проверяется сам
расчёт, а не интерфейс.

Распознавание текста проверяется на настоящей записи:

```bash
# файл речи можно сделать встроенным синтезатором macOS
say -v Milena -o /tmp/s.aiff "Ой мороз, мороз. Не морозь меня."
afconvert -f WAVE -d LEI16@16000 -c 1 /tmp/s.aiff test-speech.wav

KARAOKE_SELFTEST=1 KARAOKE_ASR_E2E=$PWD/test-speech.wav npm run app:start
```

Печатает распознанный текст, число слов с метками и получившиеся строки.
Модель докачается сама. Можно задать `KARAOKE_ASR_LANG=` (пусто — определить
язык самому) и `KARAOKE_ASR_MODEL=base`. По умолчанию берётся `small` —
крупная модель, ровно та, что стоит в приложении; `base` вдвое быстрее,
но слышит хуже.

Годится любой файл, который открывает само приложение, — mp3 и m4a в том
числе, переводить в wav не нужно. Синтезатор речи для проверки распознавания
почти бесполезен: беды вылезают только на настоящем пении, так что для
серьёзной проверки берите живую песню.

Ещё переменные:

* `KARAOKE_ASR_SEP=1` — сначала выделить вокал нейросетью и распознавать
  уже его. Это тот путь, ради которого всё задумано: по чистому голосу
  ошибок заметно меньше, чем по полному миксу. Небыстро — разделение
  трёхминутной песни занимает пару минут само по себе.
* `KARAOKE_ASR_DEBUG=1` — печатать разбор по каждому 30-секундному окну:
  что решил сторож зацикливания и переслушивал ли он окно. Нужно, когда
  подбираете пороги в `whisper-worker.js`.

### Проверка подгонки своего текста

Главный способ работы проверяется той же командой, только с файлом
правильного текста:

```bash
KARAOKE_SELFTEST=1 \
  KARAOKE_ASR_E2E=$PWD/песня.mp3 \
  KARAOKE_ASR_ALIGN=$PWD/текст.txt \
  KARAOKE_ASR_SEP=1 \
  KARAOKE_ASR_DUMP=/tmp/слова.json \
  npm run app:start
```

Печатает строку `FIT-E2E` с цифрами, по которым и видно, получилось или
нет. На что смотреть:

* **`доляОпор`** — главная цифра: какая часть слов текста получила
  настоящее время, а не растянута между соседями. На живой песне с
  чистым вокалом это около 0,8.
* **`монотонно`** и **`студияПорядокСтрок`** — времена обязаны строго
  возрастать, ничего не должно налезать друг на друга.
* **`покрытие`** — доля длины песни, на которую легла разметка. Заметно
  меньше единицы бывает честно (песня кончается проигрышем), а вот 0,5
  означает, что разметка сжалась к началу.
* **`самаяДлиннаяРастяжка`** — самый длинный кусок без опор, в секундах.
* **`сомнительныхСтрок`** — сколько строк помечено знаком `≈`.
* **`строки`** и **`опорыПоСтрокам`** — глазами сверить несколько строк
  с тем, где их реально поют.

Две переменные ускоряют работу над самим выравниванием:

* `KARAOKE_ASR_DUMP=<файл>` — сохранить услышанные слова с метками;
* `KARAOKE_ASR_WORDS=<файл>` — взять их оттуда вместо нового прогона
  нейросети. Подгонка тогда считается за секунду, и пороги в `align.js`
  можно подбирать, не слушая песню заново по три минуты.

### Проверка сцены: концы строк и проигрыши

В том же `FIT-E2E` есть раздел **`сцена`** — то, что человек увидит
в караоке и в видео. Считается теми же `lineSpan` и `stagePhase`, что
рисуют настоящую сцену, поэтому цифрам можно верить:

* **`проигрышей`** и **`проигрыши`** — сколько нот `♪ ♪ ♪ ♪ ♪` и где именно;
* **`паузы`** — все промежутки между строками. По ним видно, каким мог бы
  быть порог `BREAK_MIN` и не жмётся ли он к какой-нибудь настоящей паузе;
* **`строки`** — у каждой `сырое` (что дала подгонка), `старт` (куда
  подтянул голос), `сдвиг`, `конец` и `длина`;
* **`кусковГолоса`** и **`куски`** — что нашла речевая активность
  на вокальной дорожке. Если кусков подозрительно мало, значит пороги
  `VOICE_ON_DB` / `VOICE_OFF_DB` в `app.js` склеили песню в одно пятно.

Ещё две переменные — про вокальную дорожку:

* `KARAOKE_VOICE_DUMP=<файл>` — сохранить огибающую голоса после
  разделения (base64, около 23 КБ на три минуты);
* `KARAOKE_VOICE=<файл>` — подставить её вместо нового разделения.

Вместе с `KARAOKE_ASR_WORDS` это даёт полный прогон сцены за десяток
секунд вместо пяти минут — на живой песне, с настоящим голосом:

```bash
KARAOKE_SELFTEST=1 \
  KARAOKE_ASR_E2E=$PWD/песня.mp3 \
  KARAOKE_ASR_ALIGN=$PWD/текст.txt \
  KARAOKE_ASR_WORDS=/tmp/слова.json \
  KARAOKE_VOICE=/tmp/голос.b64 \
  npm run app:start
```

Огибающую и слова перед этим надо один раз выгрузить настоящим прогоном
с `KARAOKE_ASR_SEP=1`, `KARAOKE_ASR_DUMP=` и `KARAOKE_VOICE_DUMP=`.

## Как выпустить новую версию приложения

Полный цикл, все шаги обязательны.

### 1. Поднять номер

```bash
node bump-version.js app 1.2.0
```

### 2. Собрать установщики

```bash
npm run app:build:mac    # macOS, Apple Silicon → desktop/dist/*.dmg
npm run app:build:win    # Windows x64 и ARM   → desktop/dist/*.exe
npm run app:build        # сразу оба
```

Windows-сборка делается прямо на Маке, ничего доустанавливать не надо.

**Обязательно посмотри вывод сборки.** Там должны быть строки:

```
• подписываем ad-hoc      15 объектов
• подпись проверена       ok
```

Если их нет — сборка для macOS получится «повреждённой» и не запустится.
Причина всегда одна: сломался хук `desktop/build/afterPack.js`.
Проверить, что он на месте:

```bash
grep -c codesign desktop/build/afterPack.js    # должно быть больше нуля
```

### 3. Проверить сборку

```bash
codesign --verify --deep --strict "desktop/dist/mac-arm64/Karaoke Punch.app"
```

Тишина в ответ — значит всё хорошо.

### 4. Выложить релиз

Через сайт GitHub: **Releases → Draft a new release**.

- Тег: `v1.2.0` (обязательно с буквой `v`)
- Приложить оба файла из `desktop/dist/`
- **Переименовать их латиницей** перед загрузкой, например
  `Karaoke-Punch-1.2.0-macOS-arm64.dmg`. С кириллицей в имени
  прямые ссылки ломаются на кодировке.

### 5. Обновить ссылки на сайте

В `index.html`, блок «Версия для компьютера» (секция `id="desktop"`) —
заменить в двух ссылках `v1.1.0` и номер в имени файла на новые. Затем:

```bash
node bump-version.js site 1.3.0
npm run app:sync
git add -A && git commit -m "Выпуск 1.2.0" && git push
```

Установленные приложения увидят новую версию сами — они раз в 6 часов
спрашивают GitHub и показывают полосу со ссылкой на скачивание.

## Как поменять логотип

1. Положить новый квадратный `logo.png` в корень (лучше 1024×1024 и больше)
2. `node make-icons.js`
3. Проверить сайт, пересобрать приложение

Скрипт сам сделает все размеры: иконки для вкладки браузера и ярлыка
на телефоне, `icon.icns` для macOS, `icon.ico` для Windows, водяной знак
для видео и копию логотипа для шапки приложения
(`desktop/renderer/logo.png` — папка `icons/` в сборку не едет).

**Про углы.** Логотип нарисован скруглённым, но исходник непрозрачный,
и на Windows у значка были видны белые уголки. Скрипт вырезает углы
маской: радиус 196 px на 1024 — он измерен по картинке (подгонка
окружности по границе рисунка дала 178 px сверху и 192 px снизу),
плюс несколько пикселей запаса на кайму сглаживания. Маска рисуется
в размер каждой иконки, поэтому `.ico` собирается из отдельно
подготовленных размеров, а не через `icon:auto-resize`.

**Про каталог иконок в `Karaoke Punch.exe`.** Если заглянуть в exe
разбирателем ресурсов, каталог `RT_GROUP_ICON` врёт про длину двух самых
крупных значков: у 256×256 записано 8232 байта вместо 270376, у 128×128 —
2088 вместо 67624. Оба числа — остаток от деления настоящего размера
на 65536: длина где-то усечена до двух байтов. Сами картинки (`RT_ICON`)
целы, врёт только запись в каталоге. Это промах не наш: иконку в exe
кладёт `app-builder rcedit` — переписанный на Go rcedit из
`app-builder-bin`, к которому electron-builder обращается, когда собирает
под Windows не на Windows. У `icon.ico` и у самого установщика NSIS
каталог верный.

Чинить нечего: Windows берёт длину значка из таблицы ресурсов PE,
а не из этой записи, и рисует всё правильно. Проверено на настоящей
Windows 11 — Проводник «Огромные значки», ярлык на рабочем столе,
панель задач и Alt+Tab показывают полноцветный значок без искажений.

## Частые грабли

**«Правки не применяются» на сайте.** Кэш браузера. **Cmd+Shift+R**.
Если и это не помогло — проверь, что поднял версию: `node bump-version.js`.

**«Приложение повреждено» на macOS.** Сборка без подписи. См. шаг 2
выпуска: в логе должно быть «подпись проверена ok».

**Приложение не запускается после скачивания.** Так и должно быть при
первом запуске — оно не заверено у Apple. Лечится один раз:

```bash
xattr -dr com.apple.quarantine "/Applications/Karaoke Punch.app"
```

**Сайт вечно предлагает обновиться.** Разъехались `app.js` и
`version.json`. Проверить: `node bump-version.js` — он предупредит.

**`npm run sync` ругается «не нашёл блок».** На сайте переставили или
переименовали кусок разметки, за который цепляется скрипт. Открой
`desktop/sync-renderer.js` — там в комментариях написано, что он ищет,
и поправь либо разметку, либо скрипт.

**Самопроверка падает «Invalid or unexpected token».** Проверочный код
вставляется в страницу шаблонной строкой (`executeJavaScript` в
`desktop/main.js`), поэтому обратная косая внутри него обязана быть
удвоена: `\\d` в файле — это `\d` на странице, а `\d` молча превращается
в `d`, и проверка начинает мерить не то. То же с `\\n` внутри строк.

**Пропали файлы движка после `git clean`.** Вернуть:
`npm --prefix desktop run setup`

**«Electron failed to install correctly».** Установка Electron оборвалась
на распаковке. Починить: `npm --prefix desktop run fix` — распакует из кэша.
Если и это не помогло, удалить `desktop/node_modules/electron` и повторить
`npm run app:install`.

## Как это устроено внутри

Кратко, чтобы было понятно, куда лезть.

**Сайт** — три файла без сборщика и зависимостей. `app.js` разбит на
разделы комментариями: аудио-движок, шаги студии (песня → текст →
редактор → караоке), оформление, экспорт.

**Приложение** — то же самое в окне Electron плюс удаление вокала
нейросетью UVR-MDX-NET-Inst_HQ_3, ровно той, которой считает UVR5.
Расчёт идёт в фоновом потоке окна на WebAssembly: нативная версия
библиотеки внутри Electron падает. Модель (64 МБ) скачивается при
первом использовании и лежит в папке настроек приложения, а не
в репозитории.

**Подгонка своего текста под песню** (`renderer/align.js`) — главный
способ работы со вторым шагом. Идея простая: свободное распознавание
пения врёт в буквах, но время называет довольно точно — слово услышано
там, где его действительно поют, просто записано криво. Значит, буквы
берём у человека, а времена у нейросети.

Технически это выравнивание двух последовательностей слов: что услышала
модель и что вставил пользователь.

1. Оба ряда нормализуются: нижний регистр, ё→е, прочь знаки препинания,
   цифры разворачиваются в слова («4» → «четыре») — иначе отсчёт в песне
   теряет опоры на ровном месте.
2. Выравнивание — Нидлман—Вунш, но сравнение не строгое, а по похожести:
   `1 − расстояние Левенштейна / длина` плюс небольшая надбавка за
   совпавшее начало слова (пение съедает окончания чаще, чем корни).
   Порог `MATCH_MIN = 0,6`: «пабричном» и «фабричном» сцепляются,
   «шагала» и «сжигала» — уже нет.
3. Ходов пять, а не три: кроме «слово ↔ слово» и пропусков есть склейки
   «одно слово ↔ два услышанных» и наоборот — модель то делит распев на
   части, то приклеивает предлог к слову.
4. Текст пользователя выравнивается целиком, а распознанному разрешено
   свободно свисать с обоих концов: болтовня до и после песни ничего
   не стоит.
5. Совпавшие слова получают настоящее время — это **опоры**. Остальные
   раскладываются между соседними опорами пропорционально числу слогов
   (гласных): длинное слово поётся дольше короткого. До первой опоры и
   после последней текст отматывается на столько, сколько нужно этим
   слогам по средней скорости пения в этой же песне.
6. Порядок жёстко возрастающий: метки самой нейросети изредка идут
   вспять, такие опоры выбрасываются.

Строки собираются ровно так, как их разбил человек: перевод строки —
граница строки, пустая строка — разделитель куплетов, в разметку не идёт.
Строка, где опор меньше трети, помечается «сомнительной» — в списке
строк редактора у неё стоит знак `≈`. Пометка снимается, как только
человек поправил метку руками.

Повторяющиеся припевы отдельной обработки не требуют: выравнивание
последовательное и порядок сохраняет, поэтому второй припев цепляется
за второе исполнение. Строки, которых в песне нет (названия куплетов),
просто остаются без опор и разметку не ломают — они получают время в
щели между соседями и помечаются знаком `≈`.

**Свободное распознавание текста песни** — Whisper через transformers.js,
тоже в фоновом потоке. Нужно, когда текста песни нет под рукой; это
черновик, а не готовый результат. Устроено так же: модель качается при первом
использовании в `<папка настроек>/models/` и отдаётся странице по адресу
`app://bundle/models/…` — обработчик схемы в `main.js`. Тонкости, на
которых легко споткнуться:

- нужны сборки **`_timestamped`**: обычные экспортированы без внимания
  декодера к кодировщику, а без него меток по словам не получить;
- `graphOptimizationLevel: 'disabled'` обязателен: оптимизатор свежего
  onnxruntime падает на квантованной сборке Whisper;
- пути к движку задаём поимённо, иначе библиотека просит сборку
  `asyncify` — она нужна только для WebGPU и весит вдвое больше;
- HuggingFace отвечает **относительными** адресами при перенаправлении,
  их надо достраивать, иначе загрузка молча висит;
- прогресс и отмена идут только через `streamer`: старое
  `callback_function` библиотека больше не вызывает, и полоса молча
  замирала на 10% до самого конца. Насколько далеко зашли, видно
  по служебным меткам времени в потоке токенов.

Разделение вокала отдаёт и чистый голос: распознавание слушает его,
а не полный микс — так заметно точнее. И не только распознавание —
на нём же держится вся сцена.

### Смена тональности

Песня записана в тональности того, кто её пел. Чужой голос в неё
попадает не всегда: где-то не хватает низа, где-то припев уходит выше,
чем берётся. Сдвиг на ±полутона возвращает песню в удобный диапазон,
а темп и длина при этом не меняются вовсе.

**Почему заранее и целиком, а не на лету.** Тональность выбирают ОДИН
РАЗ перед пением, поэтому считать её в живой цепи незачем — а цена
реального времени велика: пришлось бы врезать в цепь узел и учитывать
его задержку и в плеере, и в расписании отрезков оригинала, и в записи
видео. Считая заранее в новый буфер той же длины и подменяя им
звучащий, мы не трогаем ничего: плеер, отрезки, выгрузка `.wav`
и запись видео получают буфер прежней длины с прежней разметкой
и знать не знают, что песню перенесли в другую тональность.

**Почему длина обязана совпадать отсчёт в отсчёт.** Вся разметка
студии — это времена: строки, слова, огибающая голоса, сетка долей,
отрезки оригинала. Уедь длина хоть на отсчёт — уедет всё, и человек
узнает об этом, только когда запоёт мимо. Поэтому длина выхода задана
жёстко самим устройством пересчёта, а не получается «примерно такой»;
а `сдвинутьБуфер` в `app.js` ещё и отказывается подставлять буфер
не той длины.

**Сдвигаются ОБЕ дорожки** — и минусовка, и оригинал. Оригинал звучит
на отрезках, размеченных как «здесь поёт запись», и остаться
в прежней тональности он не может.

**Считаем всегда от нетронутого.** Чистые буферы лежат отдельно, и
«+2» после «−3» считается от исходника, а не от уже сдвинутого. Иначе
качество падало бы с каждым шагом, а «назад в ноль» не возвращало бы
исходный звук. Ноль полутонов не считается вовсе — это те же самые
чистые буферы.

**Чем считаем и какой ценой.** Своим фазовым вокодером на чистом JS
(`pitch-worker.js`), в рабочем потоке, с отчётом о ходе — как
разделение вокала.

Готовая сборка Signalsmith Stretch в npm есть (`signalsmith-stretch`,
MIT, качество лучше нашего), но взять её нельзя по трём причинам сразу:
собрана она ТОЛЬКО как AudioWorklet — а в рабочем потоке AudioWorklet
не существует; модуль подкладывается через `blob:`-адрес, а считает
WebAssembly — и то и другое запрещено политикой безопасности сайта
(`script-src 'self'`), ослаблять которую ради тональности нельзя;
собрать библиотеку самим — это emscripten, которого на машине нет.

Само КПФ живёт отдельным файлом `fft.js`: то же преобразование нужно
счётчику темпа (`tempo.js`), а две копии одного кода — это починка
в одной из них и молчаливая ошибка в другой. Рабочие потоки подтягивают
его через `importScripts('fft.js' + location.search)` — хвост с номером
версии обязателен, иначе браузер отдал бы потоку файл прошлой сборки
из кэша.

Устройство вокодера: КПФ с окном Ханна около 46 мс, шаг синтеза
постоянный (четверть окна), шаг анализа плавает и равен ему, делённому
на `r = 2^(полутонов/12)` — так запись растягивается в `r` раз, не
меняя высоты. Потом она пересчитывается обратно в `r` раз оконным
sinc-ядром (со срезом `1/r` при сжатии, иначе верх заворачивался бы
вниз призвуком) — длина возвращается к исходной, а вся высота
умножается на `r`. Фаза между кадрами продвигается по истинной частоте
полосы, а не «как было», и синхронизируется по вершинам спектра
(identity phase locking, Laroche & Dolson): фазовые отношения внутри
вершины остаются нетронутыми, иначе голос звучал бы «водянисто».
На резком ударе поправка сбрасывается — атака иначе размазывается.

**Каналы обрабатываются связанно**: поправка считается по СЕРЕДИНЕ
(полусумме каналов) и применяется к левому и правому одинаково.
Разница фаз и уровней между каналами сохраняется точно. У нас это
критично вдвойне: минусовка сделана вычитанием середины, и любая
рассогласованная правка вернула бы в неё вокал. Оба канала едут через
одно КПФ (левый в вещественной части, правый в мнимой) — по одному
прямому и обратному преобразованию на кадр вместо трёх и двух.

Цена: около 10–15 секунд на трёхминутную песню, и дорожек две
(оригинал и минусовка), то есть примерно 20–30 секунд на выбор
тональности. Поэтому посчитанное лежит в кэше по числу полутонов —
возврат к прежнему выбору мгновенный. Кэш держит не больше четырёх
тональностей: пара буферов трёхминутной песни — это под полтораста
мегабайт, все четырнадцать полутонов в память не поместятся. Кэш
сбрасывается при смене песни, при загрузке своей минусовки и после
разделения нейросетью.

Предел ±7 полутонов — решение студии о том, что предлагать человеку
(дальше гласные уезжают в «бурундука» или в «бочку»), а не граница
движка: сам вокодер умеет больше, и самопроверка гоняет его на целую
октаву.

**Что проверяется числами** (признак `тональность` в самопроверке
приложения): длина обеих дорожек — отсчёт в отсчёт; высота — синус
220 Гц на +12 полутонов читается как 440, на −12 как 110, на ±2 как
246,9 и 196,0 (частота меряется автокорреляцией, как темп, только
вершина берётся первая выше порога, а не самая высокая — иначе
промах ровно на октаву); стереокартина — корреляция каналов уезжает
не больше чем на 0,05, а чистая середина после сдвига остаётся чистой
серединой (сторона ниже −60 дБ: это и есть доказательство, что правка
у каналов одна и та же); тишина остаётся тишиной; ноль полутонов
возвращает ТОТ ЖЕ САМЫЙ буфер, а прогнанный через движок силой
расходится с исходником на 9·10⁻⁸; кэш не считает дважды.

На настоящей музыке замерено (три минуты, ±2 и ±5 полутонов): длина
совпадает всегда, среднеквадратичный уровень падает на 0,2–0,7 дБ,
корреляция каналов уезжает на 0,008–0,029. Пик при этом растёт —
у песни, сведённой в потолок, до 1,6: сдвинутые фазы перестают
складываться так же ровно, как их сложил мастеринг. Ловит это тот же
страховочный лимитер, который стоит в конце общей цепи и уже держит
сумму «оригинал + минус».

#### Как это выглядит для человека

**Где.** Шаг «Караоке», окно «Оформление», закладка **«Звук»** — первым
блоком, над эквалайзером. Это настройка звучания, а не разметки, и
стоит она там же, где остальное про звук. Крупное число («+2», «−3»,
«0»), стрелки по бокам, «В ноль» под ними и строка о том, что сейчас
звучит на самом деле.

**Стрелки не считают.** Один пересчёт — 20–30 секунд на трёхминутную
песню (считаются и минусовка, и оригинал). Перебирать
стрелками, запуская счёт на каждый шаг, значит потратить полчаса на
выбор из четырнадцати значений. Поэтому стрелки только ВЫБИРАЮТ, а
считает кнопка **«Применить»** — она появляется ровно тогда, когда
выбранное ещё не звучит, а число до нажатия приглушено. Исключение
одно, и оно важнее правила: если выбранное уже посчитано (лежит
в кэше) или это ноль, ждать нечего — ставим сразу, прямо по стрелке.
Поэтому «туда-обратно» между двумя опробованными тональностями идёт
мгновенно, а «В ноль» — всегда мгновенно.

**Пока считает** — окно с полосой, как у разделения вокала и
распознавания, и в нём **«Отменить»**. Отмена терминирует рабочий
поток; прежняя тональность остаётся на месте целиком, потому что
буферы подменяются только после того, как посчитаны ОБЕ дорожки, —
до этого в студии лежит ровно то, что звучало. Выбор при отмене
возвращается к звучащему, чтобы орган управления не врал.

**Можно менять прямо во время пения.** Источники перезапускаются
с той же секунды: играло — играет дальше, стояло — осталось стоять
на месте. Щелчка нет — звук вводится тем же линейным нарастанием
за 12 мс, которым живёт и перекрёстное затухание на отрезках
оригинала (`ОТРЕЗОК_ФЕЙД`); второго способа гасить щелчки в студии
заводить не стали.

**Что переживает перезагрузку.** В проекте и в черновике живёт ВЫБОР
числом (`key`), а не посчитанные буферы: пара сдвинутых дорожек
трёхминутной песни — под полтораста мегабайт, в `localStorage` такое
не положить да и незачем. Выбранная тональность видна и в чипе памяти
рядом с именем песни (ноль не показывается вовсе — чип узкий).

**Когда считается после открытия.** Не при открытии. Студия не имеет
права молча замирать на полминуты, поэтому выбор просто помнится,
а пересчёт запускается при приходе на шаг «Караоке» — там, где поют, —
и говорит о себе отдельной строкой: «Возвращаем тональность +3,
выбранную в прошлый раз…». Прервать можно той же кнопкой. Сам собой
досчитывается ТОЛЬКО выбор, пришедший из памяти: выбранное стрелками
и не применённое не считается никогда — раз человек нарочно не нажал
«Применить», внезапной паузы при возврате на шаг быть не должно.

**А возврат в ноль случается сразу, при открытии черновика.** Ноль —
это нетронутый исходник, он всё время лежит в `тон.чистые`, считать
нечего. Беда, которую это лечит: черновик открывали поверх работы, где
звучало `+5`, а в черновике тональность `0`. `тон.выбран` становился
нулём, чип прятался (по его мнению выбранное совпало со звучащим), —
а `тон.полутонов` оставался пятёркой, и из колонок до самого шага
«Караоке» шла чужая высота. Человек размечал строки под звук прежней
тональности.

**Экспорт звучит в выбранной тональности.** Минусовка `.wav`, видео
и «проверить звук» берут буферы из состояния, а там уже лежат
сдвинутые. Это проверяется числами, а не на веру (см. ниже).

### Где строка кончается и где проигрыш

Раньше конец строки был выдуман: если до следующей строки больше шести
секунд, строка объявлялась спетой ровно за четыре, остальное — проигрыш.
На распеве подсветка обрывалась на полуслове, а коротких проигрышей
набегало столько, что петь было сумбурно: на трёхминутной песне
шестнадцать штук, из них тринадцать короче двух с половиной секунд.

Теперь у сцены есть два настоящих источника: **времена по каждому слову**
(разметка вручную или подгонка текста) и **огибающая громкости чистого
вокала**. Вся арифметика — в `lineSpan` и `stagePhase` в `app.js`, оттуда
её берут и караоке, и просмотр редактора, и отрисовка видео. Иначе
записанный ролик разошёлся бы с тем, что человек видел на экране.

**Огибающая голоса.** Держать вокальную дорожку целиком незачем: после
разделения из неё считается среднеквадратичная громкость окном 20 мс
с шагом 10 мс — сто отсчётов в секунду, по байту на отсчёт. Громкость
пересчитывается в децибелы от 95-го процентиля дорожки (не от максимума:
на процентиль не влияют ни редкие всплески, ни длинные куски тишины),
и байта хватает на шестьдесят децибел. Три минуты песни — семнадцать
килобайт, они лежат в проекте вместе с текстом и переживают перезагрузку.

Где голос звучит, определяется двумя порогами, а не одним, — иначе на
границе дребезжит: голос «включается» на −25 дБ и «выключается», только
упав ниже −35 дБ. Куски короче 0,18 с выбрасываются, паузы короче 0,3 с
склеиваются — это вдохи между словами, а не тишина.

**Конец строки** берётся, в порядке важности: конец, выставленный руками
в редакторе (`line.ручнойКонец`); конец последнего слова; следующая
строка, если она идёт сразу; и только когда не известно ничего — средняя
длина строки в этой же песне. Поверх всего: если в этот момент голос ещё
звучит, строка тянется до конца пения, но не больше чем на четыре секунды
и не дальше следующей строки. Хвост достаётся последнему слову — на
распеве тянется именно оно, а не вся строка разом. Если конец
последнего слова выставлен руками (`ручнойКонец` уже у самого слова,
см. «Пауза между словами» ниже), хвост остаётся за строкой, а слово
кончается там, где сказано.

Важная тонкость: конец, пришедший от распознавания, — это всего лишь
конец последнего слова, и продлевать его голосом не только можно, но
и нужно. Поэтому «ручной конец» помечается отдельно, а не угадывается
по тому, что поле `end` заполнено.

**Начало строки** подтягивается к ближайшему вступлению голоса в узком
окне: ±0,7 с, а для строки со знаком `≈` (подгонка сама призналась, что
время подобрано на глазок) ±1,5 с. Окно вдобавок не шире половины
расстояния до соседей — иначе две строки подтянулись бы к одному
вступлению и налезли друг на друга. Метки слов едут за строкой ровно на
ту же величину, и только если сдвинутая строка налезает на следующую,
она ужимается.

**Проигрыш** ставится, только если между концом строки и вступлением
следующей голоса нет **восьми секунд и дольше**. Порог выбран по живой
песне: там паузы между строками — от 0,02 до 2,3 с, а настоящих
инструментальных кусков два, 16 и 30 секунд. Между 2,3 и 16 секундами
на этой песне нет ничего, так что любой порог от 3 до 15 даёт один и тот
же ответ; восемь секунд стоят посреди этого пустого места и совпадают
с тем, что принято в нынешних караоке. Настройкой порог не сделан
намеренно: ручка, которую нечем осмысленно крутить, только мешает.

**Нот пять, а не три** (`BREAK_TEXT`, `BREAK_TEXT_FRAME` в `app.js`).
Три читались как многоточие, а не как «здесь играет музыка», и закраска
по нотам шла на длинном проигрыше слишком крупными шагами. В подгонку
единого кегля (`stageFit`) ноты намеренно НЕ входят: кегль считается по
строкам песни, а ноты — не строка песни. Зато у них свой потолок: если
при песенном кегле пять нот в отведённую ширину не влезают (короткая
песня задирает кегль до потолка `FIT_MAX_UNITS`, а ползунок «Размер»
умеет удвоить его ещё раз), ужимаются они одни — `breakSizeDOM` кладёт
кегль поменьше в `--st-fs-break`, кадр видео считает его же функцией
`кегльНот`. Переносить ноты нельзя: перенесённые читаются как две
строки текста.

**Сплошное слово рвётся по буквам.** Строке, не влезшей даже на самом
мелком едином кегле, ставится класс `.wrap` — `white-space: normal`,
и она раскладывается на несколько рядов. Но рвать слово из трёхсот
знаков без пробелов браузеру негде, и оно уезжало за край сцены
(у неё `overflow-x: hidden`): на экране оставалась четверть — замерено,
1301 px содержимого в коробке шириной 419. Поэтому у `.stage-line.wrap`
стоит `overflow-wrap: anywhere` — `anywhere`, а не `break-all`: пока
в строке есть пробелы, перенос идёт по ним, как и раньше. Тот же приём
стоит у подписей простукивания. Кадр видео такое слово пока не рвёт
(`rowsOf` раскладывает по словам, а слово тут одно) — на экране это
чинится, в записи нет.

Короткие паузы не отмечаются нотами — о вступлении следующей строки
предупреждает отсчёт из трёх точек (`COUNT_LEAD`, `COUNT_MIN_GAP`),
а сама строка стоит допетой. Это то, как ведут себя нынешние караоке.

**Где стоят точки.** Раньше их место считалось относительно ОДНОЙ
строки: на месте нот проигрыша, а если нот нет — «чуть выше той, что
вот-вот зазвучит». Стоит развести ползунки «Место первой» и «Место
второй», и это «чуть выше» приходилось ровно на строку, которую поют
сейчас: точки ложились на слова. Теперь место ищется по прямоугольникам
всех видимых строк — `свободноеМесто` в `app.js` собирает щели между
ними и ставит точки в ту, которая и вмещает ряд целиком (`COUNT_BAND` =
0,9 кегля), и ближе всего к желаемому месту. Если текст занял
поверхность целиком и свободной щели нет вовсе, точек не будет совсем:
лучше без подсказки, чем поверх текста (на сцене это класс `no-room`,
он же не даёт спрятаться нотам проигрыша). Арифметика одна на две
поверхности — живая сцена подаёт в неё коробки из DOM, кадр видео свою
раскладку; в просмотре редактора отсчёта нет вовсе.

**Подложка под текстом** (`scrimStops`, `scrimGeom`, `scrimCss`
в `app.js`) — мягкая тёмная полоса ровно там, где строки, вместо
затемнения всего кадра: картинка остаётся видна. Беда, которую это
лечило: высота полосы была постоянной (четырнадцать процентов вокруг
середины между местами строк), а места строк ездят ползунками. Разведи
их на 46 % и 67 % — и вторая строка повисала на голой картинке. Кегль
полоса не учитывала вовсе, хотя строка занимает высоту, а не линию.

Теперь высоту считает `scrimGeom` по НАСТОЯЩИМ местам строк — тем же
`slotPositions`, который их расставляет, — и по настоящей высоте строки.
Плато полной силы накрывает обе строки целиком плюс запас
(`SCRIM_MARGIN` = 1,5 % высоты), дальше идёт спад. Ползунок «Высота
подложки» (`scrimSize`, закладка «Цвет» рядом с силой подложки) множит
всю полосу: 100 % — ровно под текстом, 50 % — узкая лента, 200 % —
широкая. Настройка живёт в проекте и в черновике `.kpunch` и попадает
в видео; ключ новый, прежнего умолчания у него не было, поэтому в старые
проекты он приезжает сам, без переноса поколением (`STYLE_GEN`).

В раскладке «строки меняются местами» столбец бывает во весь кадр (до
девяти строк), и накрывать его целиком полной силой означало бы
затемнить картинку целиком — ради отказа от чего подложка и заведена.
Там полной силой берётся середина, где идут текущая и следующая строки,
а до края столбца достаёт спад: подложка слабее, но она есть.

Рисуется полоса в двух местах — градиентом CSS на живой сцене
(`--st-scrim`, ставит `fitStageLines`: высота считается от кегля, а
кегль известен только после замера ширины поверхности) и градиентом
канваса в кадре видео. Остановки у обеих одни и те же, из одного
`scrimStops`, а геометрия — из одного `scrimGeom`: сцена и кадр оба
16 : 9, и кегль в обоих равен одной и той же доле ширины. Самопроверка
меряет расхождение числами, сейчас оно 0,11 % высоты.

**Без вокальной дорожки** — на сайте всегда, в приложении пока не убран
вокал нейросетью — работает ровно то же самое, только без подтяжки
к голосу и без хвоста распева: конец строки берётся из времён слов,
а где нет и их — из средней длины строки в песне. Ничего не падает,
проигрышей всё равно становится сильно меньше прежнего.

### Что в памяти студии и черновик файлом

Студия помнит **одну работу за раз** — текст, времена, отрезки
оригинала, оформление, фон и огибающую голоса. Всё это лежит в проекте
(`собратьПроект` → `localStorage`, ключ `karaoke-project`).

**Что в памяти — написано заранее.** Раньше об этом узнавали только из
вопроса «открыть другую песню?», то есть уже занеся руку над чужой
разметкой. Теперь то же самое видно до того: чип в ряду шагов (имя
песни и «размечено N из M» в подсказке) и строка над зоной загрузки на
первом шаге — обе собирает `обновитьПамять` по `сведенияОПамяти`. Чип
вынесен из потока, как и ссылка на руководство: ряд шагов остаётся
посередине, а высоты рабочее место не теряет ни пикселя. Разбирать
проект из хранилища `сведенияОПамяти` не станет, пока всё нужное есть
в памяти: внутри проекта огибающая голоса в base64, и `JSON.parse`
на ней не бесплатен.

**Черновик** — тот же проект, но файлом (`.kpunch`, обычный JSON;
`сохранитьЧерновик` и `открытьЧерновик`, кнопки рядом с чипом).
Хранилище браузера теряется: чистка кэша, другой браузер, переустановка
приложения — а работа над длинной песней стоит вечера.

* **Звука в черновике нет.** Песня и так есть у человека, а с ней файл
  вышел бы в десятки мегабайт. Вместо звука записано имя песни, и при
  открытии оно сверяется с тем, что загружено: не совпало — спросим.
* **Номер формата** (`ВЕРСИЯ_ЧЕРНОВИКА`) — чтобы черновик из будущей
  версии узнавался и не открывался молча наполовину.
* Поверх готовой разметки черновик открывается только с разрешения:
  вернуть затёртое будет нечем.
* Открывается он туда, где можно продолжать: песня загружена и времена
  есть — сразу в редактор, песня загружена без времён — в текст, песни
  нет — остаёмся на первом шаге, а строка над зоной загрузки говорит,
  какой файл нужен.

Самопроверка (раздел `черновик`) гоняет круг целиком: собрали проект →
потеряли работу → открыли черновик → всё на месте, и чип показывает
ту же песню.

### Дописанные строки

Человек размечает песню, вспоминает про забытый куплет, дописывает его
в текст — и на дорожке дописанных строк **нет**. Времени у них нет,
а всё, что без времени, дорожка не рисует вовсе (`syncedLines`): строку
не видно, не выбрать и не потянуть.

Поэтому дописанной строке сразу отводится место (`расставитьНовыеСтроки`
в `app.js`): промежуток между размеченными соседями делится поровну
между теми, кто в него попал, а дописанное в самый конец ложится за
последней размеченной строкой через привычную для этой песни длину
(`typicalLineDur`). Время выдуманное, поэтому строки помечаются знаком
`≈` — тем же, которым подгонка помечает свои догадки: на дорожке такой
блок пунктирный, и сразу видно, что его надо поправить.

Трогаются **только дописанные** строки — те, которым `alignByText` не
нашёл пары в прежней разметке. Строка, которую просто ещё не простучали,
времени не получает: простукивать можно с любого места, и метки после
него не выдумываются, а ждут своего удара.

### Редактор: три поверхности

Третий шаг — весь редактор. Поверхностей три, у каждой своя работа,
и они намеренно не дублируют друг друга:

| Поверхность | Чем занята |
| --- | --- |
| список строк | поиск, навигация и правка текста. В строке — номер, начало, длительность, текст и тихие пометки `≈` (время на глазок) и `♪` (про ручную разметку слов, см. ниже). **Кнопок подстройки в строке нет:** их было по восемь на строку, и они дублировали дорожку, клавиши и панель. Двойной клик перематывает песню на начало строки; во время воспроизведения список сам всплывает к текущей строке (`scrollEditListTo`) |
| инспектор | одно окно на весь редактор, двумя **сворачиваемыми** разделами: выбранное **слово** (само слово, начало, конец, длина, кольцо) и выбранная **строка** (номер, начало, конец, длина, прослушать, «♪ слова» и сброс, распределить, простучать заново, удалить, «слышу оригинал»). Заголовок окна идёт за выбором: правят слово — «Слово», не выбрано — «Строка» |
| дорожка | весь тайминг, плюс наушники: соло и уровни полос. Сколько ей высоты, а сколько трём окнам сверху, решает разделитель между ними — см. «Как делится высота» ниже |

Плюс просмотр караоке посередине, один в один со сценой: те же
места строк, тот же единый кегль, тот же значок проигрыша. Отсчёта
перед строкой в нём нет — точками в окошке 200 px мигать незачем,
а значит, и налезть на текст им там нечем.

**В списке строк два столбца времени, а не три.** Было начало, конец
и длина; конец из первых двух и выводится, то есть третьим числом
ничего нового не сообщал, а ширину занимал. Из двух возможных пар
полезнее «начало и длина»: длину сравнивают глазами сверху вниз и сразу
видят строку, которой не хватило места, а конец и так виден на дорожке
и стоит в инспекторе. Освободившаяся ширина ушла тексту строки.

**Пометка `♪` переворачивается.** Она говорит про ручную разметку слов,
и беда у неё была ровно та, от которой пометки и заводят: когда слова
размечены во всей песне, значок стоит у каждой строки и не сообщает
ничего. Поэтому, если ручная разметка есть у большинства размеченных
строк (порог `ДОЛЯ_СЛОВ` = 0,6, но не меньше `МИН_СТРОК_СЛОВ` = 4 строк
всего), помечаются, наоборот, строки, у которых её НЕТ, — приглушённым
значком с пунктиром и другой подсказкой. Ниже четырёх строк не
переворачиваем вовсе: на двух-трёх «большинство» — случайность.

**«Сбросить слова» перерисовывает и дорожку** (`resetWords`). Метки слов
нарисованы на дорожке своими штрихами, вместе с разведёнными краями
и паузами, — а сброс звал только список строк, инспектор и просмотр.
Стёртое продолжало показываться на дорожке, пока её не перерисует
что-нибудь постороннее. Самопроверка меряет это пикселями холста:
дорожка обязана поменяться на сбросе и НЕ поменяться от лишней отрисовки
следом.

**Поиск по строкам.** Над списком поле: в песне сорок-шестьдесят строк,
и нужную ищут глазами долго. Поиск по подстроке, регистр и «ё» не важны
(`нормДляПоиска` заменяет «ё» на «е» — в песнях её пишут и так и так).
Показываются только подходящие строки, но **номера остаются
настоящими**: фильтр прячет ряды, а не перенумеровывает песню, поэтому
выбор, клавиши, прокрутка за воспроизведением и правка текста в поле
работают ровно как без поиска — все они живут по номерам в
`state.lines`, а не по месту в списке. `Esc` в поле и крестик очищают,
пустое поле возвращает всё; когда не нашлось ничего, вместо пустоты
стоит надпись, иначе список выглядел бы поломкой.

**Пустую строку поле не принимает.** Стёр в списке строк весь текст (или
оставил одни пробелы) — прежний текст возвращается в поле, как только
из него ушли. Второй мыслимый ответ — считать стёртый текст просьбой
удалить строку, как кнопка «удалить», — отвергнут нарочно: строка везёт
на себе время начала, конец, пометку `≈` и метки слов, а стереть текст
можно одним `Cmd+A` и `Backspace`, случайно и не глядя. Удаление разметки
не должно быть побочным следствием опечатки. Раньше отказ был совсем
молчаливым: в `state.lines[i].text` оставалось прежнее (на сцене пелось
старое), а в поле стояла пустота — до следующей перерисовки, когда-нибудь.
Возвращаем не на каждом нажатии, а по `focusout`: обычная правка
«выделить всё и набрать заново» проходит через пустое поле, и текст
прыгал бы обратно из-под пальцев.

**Разделы инспектора сворачиваются** — «Слово» и «Строка», треугольником
у заголовка, как в инспекторе Final Cut. Беда: столбец в 210 px на
ноутбуке не помещался в окно целиком и прокручивался, а числа в нём
сверяют глазами — прокрутка тут дороже, чем кажется. Свёрнутое помнится
между сеансами (`ИНСПЕКТОР` в `app.js`, ключ `karaoke-inspector`
в `localStorage`): это привычка человека, а не свойство песни, поэтому
не в проекте. Умолчание — оба открыты.

**Время везде пишется одинаково** — минуты, секунды и доли
(`fmtTimeДоли` в `app.js`): линейка дорожки, список строк и часы
редактора показывают сотые (`1:27,44`), поля инспектора и подпись
у курсора при перетаскивании — тысячные (`1:27,440`). Разделитель
дробной части языковой: запятая по-русски, точка по-английски.
Беда, которую это лечило: в полях инспектора стояли голые секунды,
и одно и то же место песни читалось на дорожке как «3:10», а в поле
как «190», — сверить их глазами было нельзя. Набирать в поле можно
и так и так: `читатьВремя` понимает и `1:27,44`, и просто `87.44`.
Длина строки и слова осталась в секундах: это мера, а не место
на песне, и «0:02,564» читалось бы хуже, чем «2,564».

**Оригинал звучит по умолчанию.** Разметка ставится на слух по голосу,
без вокала человек размечает вслепую — поэтому в редакторе играет
оригинал, а не минусовка. Решает это одна функция `нуженОригинал()`:
её спрашивают и запуск звука, и смена шага, и конец прослушивания
отрывка. Раньше `forceVocal` гасили вручную из полудюжины мест, и он
залипал — ползунок вокала в караоке будто не действовал.

**Удаление строки** отменяется общей отменой: снимок истории держит и
текст строк, но применяет его только когда число строк изменилось —
иначе правка текста в поле воевала бы с браузерной отменой.

#### Как устроена дорожка

Дорожка нарисована на одном канвасе (`drawTimeline` в `app.js`):
элементов иначе набежало бы под тысячу, а перерисовка идёт каждый кадр
вместе с указателем воспроизведения. Полосы сверху вниз:

| Полоса | Что показывает |
| --- | --- |
| линейка | время, шаг подбирается под масштаб |
| **голос** | огибающая вокальной дорожки; есть только в приложении и только после удаления вокала нейросетью |
| волна | общий микс, как было и раньше |
| строки | **блоки** от начала до конца, а не точки: видно длину |
| слова | слова выбранной строки |

**Высота дорожки — доля рабочего места, а не число пикселей.** Раньше
полосы стояли жёсткими пикселями (16/18/28/38/30/20) с коэффициентом 0,8
на низком экране, всё остальное забирали три верхних окна — и дорожка
на любом мониторе выходила одного роста, хотя монтаж идёт именно по ней.
Теперь высоту дорожки целиком решает разделитель (см. «Как делится
высота» ниже), а прежние числа стали **весами** в `ВЕС_ПОЛОС`: они делят
между полосами то, что дорожке досталось. На дорожке прежнего роста
раскладка выходит прежняя. Линейка — исключение: у неё внутри строка
цифр в 10 px, расти ей некуда, и её высота так и осталась числом
(`LANE_RULER`). Последней полосе достаётся весь остаток, а не её доля:
округление по дороге теряет пиксель-другой, и внизу дорожки оставалась бы
щель, а колонка заголовков разъезжалась бы с канвасом.

Сколько пикселей досталось полосам, знает одна переменная
`высотаПолос`: её ставит `resizeTimeline` по живой высоте канваса,
а `timelineLanes()` только делит это число. Мерить что-то в документе
внутри `timelineLanes()` нельзя — её зовут и на каждый кадр отрисовки,
и на каждую проверку попадания.

**Поле сверху и снизу у канваса убрано** (`.tl-canvas-wrap`, было
`0.5rem 0.6rem`, стало `0 0.6rem`). Колонка заголовков начиналась
вплотную к рамке, а канвас — восемью пикселями ниже: подписи полос
стояли не против своих полос, и на «минусовке» это было видно. Заодно
эти шестнадцать пикселей вернулись самим полосам.

Слева от канваса — колонка заголовков полос (`.tl-heads`), обычный DOM,
а не рисунок: подписи читаются как настоящий текст и переводятся сами.
Строит её `renderTimelineHeads` по тем же высотам, что считает
`timelineLanes()` — вызывается и при пересчёте дорожки (`resizeTimeline`),
и при смене языка, иначе после переключателя языка подписи оставались бы
на прежнем.

У полос, у которых есть свой звук (оригинал, голос, минусовка), в колонке
стоит кнопка **S — «слушать только это»** (`переключитьСоло`, `editor.solo`).
Отдельного файла с голосом у студии нет: голос — это разница песни и
минусовки, поэтому «только голос» — это оригинал плюс минусовка
в противофазе (`усиленияСоло`: вокал 1, минусовка −1). Тем же вычитанием
живёт и приглушение вокала, ничего нового здесь не изобретается.
Ползунок уровня нарисован **фейдером монтажной программы**: желобок
в 6 px с внутренней тенью — будто прорезан в панели, — и круглая ручка
в 14 px со скосом (светлый верх, тень внизу), тёмной каймой и своей
тенью на желобке. До этого там были волосяная черта в 3 px и точка
в 7 px: они читались как царапина, брать их приходилось прицельно.
Скос сделан не картинкой, а наложением поверх цвета акцента, поэтому
ручка красится темой сама собой. Обе псевдоэлементные ветки на месте:
`::-webkit-slider-thumb` и `::-moz-range-thumb`.

Правила для ползунка в `style.css` записаны как
`input[type="range"].tl-gain`, а не просто `.tl-gain`, и это не
украшательство: `.tl-gain` весит (0,1,0), а общее правило ползунков
`input[type="range"]` — (0,1,1), потому что квадратные скобки считаются
наравне с классом. Общее было сильнее, и весь блок однажды не применялся
вовсе — в ряду заголовка полосы сидела чужая ручка в 16 px с ореолом
в 10 px, от неё колонка и выглядела перегруженной.

Проверять это по файлу бессмысленно: правило там было и тогда. Поэтому
раздел самопроверки `ползунокУровня` смотрит **живую страницу**, и двумя
способами сразу. Высоту самого поля ввода `getComputedStyle` отдаёт
честно — у нас 16 px, у общего правила 6, и проигравший блок виден
сразу. А ручка — псевдоэлемент, вычисленных стилей для неё Chrome не
отдаёт вовсе (возвращает стиль поля), поэтому каскад раздел разбирает
сам: собирает из `document.styleSheets` окна все правила про ручку, чья
основа подходит нашему полю, считает вес каждого селектора и складывает
их в том порядке, в каком сложил бы браузер. Подсунутая регрессия
(`.tl-gain::-webkit-slider-thumb` вместо `input[type="range"].tl-gain…`)
краснеет и прямо называет победителя. Ветка Firefox так не проверяется —
Chrome выбрасывает чужой псевдоэлемент ещё при разборе, и в
`document.styleSheets` его нет, — поэтому про неё раздел спрашивает
текст `style.css`.

Рядом с ползунком стоит **число процентов** мелким моноширинным
шрифтом — как «0.0 dB» у Volume в Final Cut: по одному положению кружка
уровень не прочитать, а сверять его приходится постоянно. Ради этих цифр
колонка заголовков стала шире на восемнадцать пикселей (132 → 150): без
них число выдавливало подпись полосы, а у канваса дорожки они не
отнимают ничего заметного.

Рядом с кнопкой — **ползунок уровня** у оригинала и у минусовки: это то,
что слышно в наушниках, пока размечаешь, а не громкость караоке (та живёт
на четвёртом шаге и уезжает в видео). «Оригинал O, минусовка M» означает
песню с усилением O и минусовку с усилением M−O (`усиленияНаушников`):
`O=1, M=1` — песня как записана, `O=0, M=1` — чистая минусовка,
`O=1, M=0,4` — голос тот же, музыка тише, так и разбирают слова.
Галка «слышу оригинал» — те же уровни двумя пресетами, поэтому она и
ползунок оригинала ходят вместе: уводишь ползунок ниже записи — галка
снимается, возвращаешь — встаёт. Иначе на экране было бы два органа
управления об одном и том же, и один из них молчал бы. Двойной щелчок
по ползунку возвращает умолчание. Принудительный оригинал (простукивание,
кольцо, прослушивание строки) не даёт увести голос ниже записи: там ловят
слова на слух.

Соло старше и ползунка вокала, и отрезков оригинала: нажали «только
минус» — значит, звучит минус, без переключений источника посреди песни.
Живёт соло **только в живом плеере и только в редакторе**: в минусовку
`.wav` и в записанное видео оно не попадает (там смесь считает
`усиленияМикса`), а при уходе с шага гасится само — кнопки, которой его
выключить, на других шагах нет.

Под дорожкой — легенда цветов (`.timeline-legend`), а под легендой —
свёрнутая справка «Как править разметку» (`<details class="editor-hint">`).
Сами шесть подписей легенды спрятаны за значком «?» (кнопка `tl-legend`,
`показатьЛегенду` в `app.js`): читают их один раз, а строку под дорожкой
они занимали всегда. Развёрнутая легенда встаёт в тот же ряд, что и
кнопка, — ничего не прыгает; состояние не запоминается, это справка на
один взгляд, а не настройка.

**Приглашение внутри пустой полосы оригинала** («протяни мышью — на этом
куске зазвучат настоящие слова») висело в рабочей области всё время, пока
полоса пуста, — то есть и у того, кто отрезки делать давно научился и
просто убрал их все. Теперь оно гаснет навсегда, как только человек сделал
первый отрезок. Признак живёт **в проекте** (`state.отрезокБыл`, ключ
`origHintDone`), а не в сессии: иначе надпись возвращалась бы после каждой
перезагрузки. Другая песня — другой проект, там приглашение снова к месту.
Раньше легенда лежала внутри справки, а сама справка стояла в самом верху
шага, над панелью управления. Оба переехали по одной причине: и цвета,
и объяснение нужны ровно тогда, когда смотришь на дорожку, а не до того,
как до неё дошли. Свёрнутая справка — одна строка, высоты рабочее место
от неё не теряет; развёрнутая **прокручивается внутри себя** и занимает
не больше трети шага (`#step-3 .editor-hint[open]` в `style.css`, высота
долей, а не пикселями). Пока она открыта, рабочим окнам разрешено сжаться
сильнее обычного. Без этого развёрнутая справка просто росла и выталкивала
редактор вместе с кнопками «← Текст» / «Караоке →» за нижний край
подложки студии — на 1280×800 это было видно сразу.
На линейке у указателя воспроизведения стоит рамка с текущим временем:
время под курсором смотрят чаще всего, и переводить ради него взгляд
на панель — лишнее движение.

Блок строки рисуется по `lineSpan` — тому же коду, по которому живёт
сцена и запись видео. Поэтому дорожка показывает не «что записано
в `line.time`», а **что на самом деле произойдёт**. Тонкой чертой внутри
блока отмечено `core` — где строка спета по словам; справа от неё
хвост распева, который тянет голос. Строка со знаком `≈` (время подобрано
на глазок) рисуется пунктиром и другим цветом. Выделенный блок обведён
ярко и со свечением (`shadowBlur`) — цвет берёт из темы (`edTheme.selRing`),
это одно из четырёх мест её акцента (см. раздел «Тема» выше).

Пока тянут границу (мышью), у курсора висит подпись с точным временем —
тысячные доли, разделитель по языку (`showDragTip`/`fmtTimeMs` в
`app.js`). Те же тысячные — в полях начала и конца в панели выбранной
строки (`sel-start`/`sel-end`, было — сотые): драгу и полю нет смысла
расходиться в точности. Всюду, где числа стоят колонкой (список строк,
эти поля, часы редактора, линейка на дорожке), — моноширинное
начертание с табличными цифрами (`font-variant-numeric: tabular-nums`,
переменная `--ed-num`), иначе колонки дёргаются при воспроизведении.

`lineSpan` для каждой строки считать на каждый кадр нельзя — внутри
медиана длин строк, то есть сортировка. Поэтому раскладка кэшируется
(`editorSpans`), а ключом служит слепок времён (`spansKey`): изменилось
хоть одно — пересчитается само.

#### Как делится высота: окна, разделитель, дорожка

Главная жалоба на редактор была короткой: **дорожка мелкая**. Верхние
окна забирали всю высоту, дорожке доставались её жёсткие сто с
небольшим пикселей, и на большом мониторе под ней просто пустовало
полэкрана.

Сделано так же, как в Logic Pro и Final Cut: между тремя верхними
окнами и дорожкой стоит **разделитель**, и сколько кому высоты — решает
человек. Разделитель (`.ed-splitter`, `завестиРазделитель` в `app.js`)
тянется мышью, слушает стрелки `↑` и `↓` с клавиатуры (по 12 px) и
возвращает умолчание двойным щелчком. Это не кнопка, а
`role="separator"` с фокусом: тянуть мышью — не единственный способ.

**Хранится доля, а не пиксели** (`karaoke-split` в `localStorage`,
умолчание `ДОЛЯ_ДОРОЖКИ` = 0,46). Пиксели, снятые с ноутбука, оставили
бы дорожку на большом экране прежней крохой; доля даёт на любом
мониторе осмысленную высоту. В хранилище доля попадает на отпускании
кнопки, а не на каждом движении: за одно перетаскивание их сотни.

Как это устроено в вёрстке: окна (`.editor-grid`) стоят «весь остаток»
(`flex: 1 1 0`), дорожка (`.timeline-wrap`) — своим числом
(`height: var(--tl-h)`), а само число ставит `применитьДеление`. Значит,
сумма «окна плюс дорожка» не зависит от того, как их поделили, и мерить
рабочее место можно в любой момент — этим и занят `рабочееМесто()`.
Складывать его из высоты шага за вычетом соседей было бы точнее на
бумаге и хуже на деле: поля и `margin` соседей в `offsetHeight` не
входят, и оценка расходилась с настоящей на десяток пикселей.

Пределы держит код, а не только CSS: окнам всегда остаётся `МИН_ОКОН`
(176 px — заголовок, поиск и пять строк), дорожке — не меньше
`МИН_ДОРОЖКИ` (140 px, ровно столько занимала вся дорожка до правки)
и не больше `МАКС_ДОРОЖКИ` (460 px: расплывшаяся по вертикали волна
читается не лучше мелкой). Нижний предел окон в CSS нарочно ниже
нашего (80 против 176) — пока делит код, до него не доходит, и
`рабочееМесто()` не мерит окна, упёршиеся в чужой предел.

Одна тонкость про справку. Развёрнутая справка («Как править разметку»)
раньше была `flex: 0 1 auto` и молча сжималась за чужой счёт — а пока
она отдаёт свои пиксели, сумма «окна плюс дорожка» перестаёт быть
постоянной, и делить становится не от чего. Теперь она `flex: 0 0 auto`:
занимает ровно свою треть (`max-height: 34%`) и прокручивается внутри
себя, как и раньше, а остаток делят окна и дорожка. Пока справка
открыта, окнам разрешено сжаться сильнее обычного
(`МИН_ОКОН_СО_СПРАВКОЙ` = 90), иначе на 1280×800 сумма минимумов
не влезала в подложку студии. Само открытие справки пересчитывает
деление — у `#editor-hint` для этого висит обработчик `toggle`.

Заодно подешевели по высоте **заголовки трёх окон**: «СТРОКИ»,
«ПРОСМОТР», «СТРОКА» читаются, но стоят 21 px вместо 29 (межстрочный
интервал 1,5 вместо общего 1,6 и вдвое меньше поля), поля внутри окон
ужаты, а у окна просмотра почти убрано поле вокруг сцены — сцена
держит 16:9 и всё равно не занимает окно целиком, а поле вычиталось
из высоты дважды.

Что это дало (высота полос дорожки, приложение, огибающей голоса нет):

| Окно | Было | Стало |
|---|---|---|
| 1440×900 | 122 px | **260 px** |
| 1280×800 | 122 px | **214 px** |

На узком экране (`max-width: 900px`) делить нечего: студия перестаёт
быть высотой в окно, всё идёт своей высотой и прокручивается страницей.
Разделитель там спрятан, а `применитьДеление` в такой раскладке
не трогает `--tl-h` вовсе (проверяет, что шаг всё ещё `display: flex`).

Стережёт всё это два раздела самопроверки. `разделитель` тянет границу
мышью и стрелками и требует, чтобы сумма «окна плюс дорожка»
не изменилась (что взяла дорожка, то отдали окна), чтобы доля попала
в хранилище и оттуда её прочитала `прочитатьДолю`, чтобы двойной щелчок
вернул умолчание и чтобы дорожка не съела окна целиком. `высотаДорожки`
подставляет странице ровно 1440×900 и 1280×800 — **эмуляцией
устройства**, а не настоящим размером окна: настоящее окно система
обрезает по рабочей области (на маке разработчика 900 превращались
в 838), и числа зависели бы от того, у кого какой монитор. На каждом
размере он требует, чтобы дорожка выросла против прежних 122 px, чтобы
сумма полос совпала с высотой канваса и с колонкой заголовков и чтобы
все четыре шага влезли в подложку студии целиком.

#### Что делается на каждом кадре редактора

Редактор — самый плотный экран студии, и на кадре у него есть законная
работа: **дорожка перерисовывается целиком под движущийся указатель
воспроизведения**. Это намеренно и это не обсуждается — холст один,
элементов на нём под тысячу, и указатель обязан ехать плавно.

Правило у общего цикла (`tickPlayer`) одно: **на кадр попадает только то,
что от кадра к кадру и правда меняется**. Само по себе едет одно — время.
Всё остальное — масштаб, выделение, правка, перетаскивание — рисует себя
там же, где меняет данные, и на общий цикл не рассчитывает.

Раньше правило нарушалось в трёх местах сразу. Числа ниже — замер живого
приложения на 120-герцевом экране (раздел самопроверки `кадрыРедактора`
меряет то же самое).

| Что делалось | Было | Стало |
| --- | --- | --- |
| стоим на паузе, 3 с | 360 отрисовок дорожки, 360 пересчётов просмотра, 360 — чужой сцены, 360 — полосы перемотки | ничего |
| играем, 5 с | 600 отрисовок дорожки **(намеренно)** + 600 пересчётов сцены караоке с 4-го шага и 600 — полосы перемотки | 600 отрисовок дорожки, и только |
| тащим границу, 3 с | 719 отрисовок холста (по две-три на кадр), 360 пересборок просмотра, из них 357 — в пустоту | 361 отрисовка (ровно раз в кадр), 2 пересборки |
| тащим границу под музыку, 3 с | 808 отрисовок, 270 прокруток списка строк — на каждом кадре; кадров при этом выходило 89 в секунду вместо 120 | 362 отрисовки, 3 прокрутки, 120 кадров в секунду |

Что было лишним и почему.

**Оба рабочих шага считались сразу.** Цикл каждый кадр звал
`updateStageFill` и `updatePlayerUI` — сцену караоке и полосу перемотки
с ЧЕТВЁРТОГО шага, — пока человек сидит в редакторе и ничего этого
не видит. Теперь их считает только тот шаг, который на экране; при
возвращении на четвёртый всё пересчитает `goToStep`.

**На паузе перерисовывалось то же самое.** Указатель стоит, дорожка
не менялась — а холст переписывался 120 раз в секунду тем же рисунком.
Теперь кадр редактора считается, только когда сдвинулось время (плюс
один кадр после остановки — на нём указатель встаёт на своё последнее
место) или когда кто-то попросил проверить просмотр заново.

**Просмотр пересобирался на каждое движение мыши.** У него был один
ключ — фаза (какая строка поётся, идёт ли проигрыш), и полтора десятка
мест по студии сбрасывали его в пустоту со значением «проверь заново».
При перетаскивании границы времена едут на каждом движении, ключ гас
на каждом движении — и просмотр собирался заново вместе с подгонкой
кегля (`fitStageLines`, замер строк холстом) и прокруткой списка строк
к текущей строке. На экране при этом не менялось ни пикселя: поётся-то
та же строка. Теперь ключей два: дешёвый фазовый `editor.stageKey` —
чтобы решить, стоит ли вообще звать перерисовку, и `editor.stageDrawn` —
слепок того, что на самом деле нарисовано (ключи, тексты, классы и места
строк). Совпал — работы нет.

Та самая прокрутка списка строк и была «событием `scroll` едва ли
не каждый кадр», из-за которого подсказки у кнопок не гасят по прокрутке
(см. «Свои подсказки у кнопок»). Сетка по-прежнему всплывает к текущей
строке — просто теперь ровно на смене строки, а не 120 раз в секунду.

**Холст рисовался по два-три раза на кадр.** За один кадр браузер
присылает несколько `pointermove`, и каждое движение перерисовывало
дорожку целиком — поверх кадровой отрисовки. Теперь на время обработки
движения мыши отрисовка откладывается до кадра (`отрисоватьВКадре`),
а пока песня играет, её и вовсе делает общий цикл: обработчики мыши
отрабатывают раньше кадровых обещаний, значит цикл рисует уже с новыми
числами. Клавиши, отпускание кнопки и самопроверка рисуют на месте,
как раньше.

**Подписи переписывались, даже когда не менялись.** Присвоение
`textContent` сносит старый текстовый узел и заводит новый, даже если
строка та же; в списке строк таких подписей полторы сотни, и `refreshTimes`
переписывал их все на каждое движение мыши. Теперь пишем только при
настоящем изменении (`писать`, `ставитьЗначение` — тот же приём, что
в `setText`). Заодно `showDragTip` читает раскладку ДО того, как что-то
написать: чтение сразу после записи заставляло браузер пересчитывать
раскладку на месте.

Стережёт всё это раздел самопроверки `кадрыРедактора`. Он меряет
настоящие отрисовки холста (по `setTransform`, который `drawTimeline`
зовёт ровно раз за отрисовку), прокрутки списка строк и записи в узлы
(подменой `textContent` и `value` — одного `MutationObserver` мало:
браузер не заводит записи, когда в узел кладут ту же строку, а `value`
у поля ввода в разметке и вовсе не отражается). Требует: на паузе — ноль
отрисовок и ноль записей; на воспроизведении — ровно по отрисовке на кадр
(меньше значит, что указатель дёргается, больше — что холст рисуется
дважды) и не больше восьми прокруток списка за 240 кадров при том, что
список всплыл и текущая строка видна; при перетаскивании под музыку —
то же самое; повторный вызов `renderEditStage`, `refreshTimes`,
`updateSelInfo` и `updateWordInfo` на неизменных данных — ноль записей
в узлы.

#### Пауза между словами

Раньше конец слова был обязан равняться началу следующего: перетаскивание
границы сваривало соседей, и паузу между словами выразить было нечем —
на распеве с проглоченным словом подсветка ехала дальше как ни в чём
не бывало.

Теперь края умеют расходиться. Пока они совпадают (`стыкли`, порог
`СТЫК` = 4 мс), это **стык** — одна ручка на двоих, и тянется он как
раньше: конец левого слова и начало правого едут вместе. Потянешь стык
с зажатым **Cmd/Ctrl** — края разъезжаются: влево уходит конец левого
слова, вправо — начало правого, второй край остаётся ровно там, где был
(`editor.одинКрай`, `wordEdgeOneCore`). Ровно так же устроено в Logic Pro
и Final Cut: обычное перетаскивание двигает стык, с модификатором —
только один край.

Разошедшиеся края ловятся по отдельности (`word-start` и `word-end`
в `timelineHit`), поэтому паузу можно и поправить, и убрать — подведи
любой из двух краёв к соседу, и они снова станут стыком. Магнит для
этого специально считает края слов ТОЙ ЖЕ строки целью (`свои`
в `точкиМагнита`): обычно своя строка целью не считается, но здесь без
соседнего края паузу не закрыть вплотную.

Поля инспектора и стрелки живут по тому же правилу: пока края сварены,
они двигают стык целиком (как раньше — набрал начало слова, сосед
подтянулся), а у разведённых краёв правят ровно тот край, о котором
поле. Слово целиком (`word-move`) ходит в своём промежутке и упирается
в соседей, но паузы вокруг себя не съедает.

Что это меняет дальше по цепочке:

* **заливка в караоке** — в паузе прежнее слово уже закрашено целиком,
  а следующее ещё нет (`wordProgress` считает по своим `start`/`end`,
  ему пауза далась даром);
* **расширенный `.lrc`** — конец слова в этом формате задаётся меткой
  следующего, поэтому паузу выражаем лишней меткой на конце слова:
  `<00:03.60>два <00:04.99><00:05.30>три`. Плееры, которые её понимают,
  гасят подсветку; остальные читают текст, как и раньше;
* **подгонка своего текста** (`align.js`) паузы делала и раньше — она
  берёт концы слов из распознавания, — просто поправить их было нечем.
  Теперь есть.

Самопроверка (раздел `паузаМеждуСловами`) держит оба поведения сразу:
обычное перетаскивание по-прежнему сваривает, с модификатором края
расходятся ровно на заданное, ручки ловятся по отдельности, заливка
в паузе стоит, в LRC появляется лишняя метка, а отмена возвращает стык.

##### Края крайних слов: пауза перед первым, конец последнего

Оставалось два сварных шва, и они держались дольше остальных: первое
слово было обязано начинаться вместе со строкой, а конец последнего
тянулся до конца строки. Жалоба пришла прямая: «не могу подвинуть
начало слова, время тоже не выставить» — выбрано первое слово, поле
«начало» недоступно, ручки у левого края нет.

**Пауза перед первым словом законна ровно так же, как между словами:**
певец вступает не сразу, а строка на дорожке начинается там, где
начинается. Поэтому у начала первого слова теперь есть всё то же, что
и у прочих краёв: поле «начало» в инспекторе, те же клавиши и ручка
на дорожке (`word-start` с `k = 0`, ловится в `timelineHit` отдельным
проходом — после внутренних границ, чтобы ничего между словами не
переставить). Ходит она в своих берегах: не левее начала строки и не
правее собственного конца минус `MIN_SPAN`. Начало СТРОКИ при этом
стоит на месте — двигается только слово. Подведёшь вплотную к началу
строки — снова стык (`стыкли`), и пауза исчезает отовсюду сама собой.

Показ это переживает без единой правки: в `lineWords` первое слово
и раньше считалось через `at(w.time)`, а не приравнивалось к началу
строки, — при `w.time > line.time` пауза выходит сама. Дальше по цепочке
всё то же, что и у паузы между словами: `wordProgress` в паузе держит
ноль, а в расширенном `.lrc` метка строки и метка первого слова просто
расходятся — `[00:02.00]<00:02.50>Раз`, лишней метки тут не нужно.

**Конец последнего слова** остался при своём правиле — но только пока
его не трогали руками. Хвост распева достаётся последнему слову, а не
всей строке разом (`Math.max(at(natEnd), end)` в `lineWords`), и это
верно: голос тянет именно последний слог. Но если конец выставлен
ЧЕЛОВЕКОМ, автоматике он больше не подчиняется — у слова для этого
свой признак `ручнойКонец`, точно такой же, как `line.ручнойКонец`
у строки, и с той же оговоркой: в разметке постарше признака нет,
поэтому живой распев, пришедший от распознавания и подгонки, остаётся
ровно таким, каким был. Признак ставит и снимает `wordEdgeOneCore`:
подвинул конец — признак встал, подвёл вплотную к концу строки —
снялся, и хвост снова достаётся слову. «Простучать слова», «сбросить
слова» и «распределить» собирают метки заново и признака не несут.

Хвост распева, оставшийся за строкой, — это не потеря: блок строки
на дорожке и сама строка на сцене живут до `sp.end` как раньше, просто
последнее слово в этом хвосте уже закрашено целиком.

Отсюда две мелочи в служебном коде. Снимок отмены (`snapshotTimings`)
кладёт признак теми же буквами, что и метка, — снимок разворачивается
обратно спредом, и переименование потеряло бы его; `snapshotEqual`
сверяет признак наравне со временами, иначе «взялись и отпустили»
считалось бы пустой правкой. Магнит при перетаскивании краёв слова
теперь считает целью и края САМОЙ строки (`свои` в `точкиМагнита`):
у начала первого слова и у конца последнего соседнего слова нет вовсе,
а вернуть их вплотную к строке надо ровно так же, как закрыть паузу
между словами.

Самопроверка (раздел `краяКрайнихСлов`) проверяет всё это числами:
ручка `word-start:0` ловится, мышью встаёт пауза 0,5 с, строка при этом
не двигается, заливка в паузе нулевая, метки строки и слова в LRC
расходятся, поле применяет число, клавиши двигают тот же край, край
упирается в собственный конец минус `MIN_SPAN` (2,72 при конце 2,80),
вплотную к строке возвращается стык, отмена возвращает как было; и
отдельно — что распев тянет конец последнего слова до конца строки
(сырая метка 6 с, показано 7,5), что выставленный руками конец
уважается (6,5 при строке до 7,5) и что вплотную к концу строки
признак снимается и распев возвращается.

#### Выделение диапазона и пропорциональное растяжение

Лечит две беды сразу.

Первая: **уехал один куплет**. Кнопки сдвига (`−1`, `−0,1`, `+0,1`, `+1`)
двигали ВСЮ разметку — то есть, поправляя один куплет, человек заодно
портил верно размеченный остаток песни. Правишь строку за строкой или
не правишь вовсе.

Вторая: **разметка «плывёт»**. Первая строка куплета стоит верно,
последняя опаздывает на секунду — темп у исполнителя чуть другой, чем
у того, кто размечал. Одним сдвигом такое не лечится в принципе: нужно
не сдвинуть, а растянуть.

**Как выделяют** (`editor.range = { from, to }` — номера строк в
`state.lines`, включительно):

* протяжкой по линейке дорожки — как «цикл» в монтажной программе.
  В выделение попадают строки, **начало** которых внутри протянутого
  времени. Одиночный щелчок по линейке без движения, как и раньше,
  перематывает и снимает выделение (`range-new` устроен по образцу
  отрезков оригинала, см. `beginOrigDrag`);
* `Shift`+щелчок по строке в списке — от выбранной строки до этой.
  Ловится на `mousedown` и гасится: иначе `Shift`+щелчок растянул бы
  выделение ТЕКСТА в поле строки, и на экране спорили бы два выделения;
* `Shift`+`↑`/`↓` — расширять с клавиатуры. `from` при этом якорь,
  `to` — край, который ведут; порядок концов не важен, читаются они
  через `строкиДиапазона`;
* `Esc` и обычный щелчок — снимают.

**Что с выделением делают:**

| Действие | Что происходит |
| --- | --- |
| тянуть середину полосы (`range-move`) | всё выделение едет на одну и ту же величину |
| тянуть край (`range-start` / `range-end`) | **пропорциональное растяжение**: противоположный край стоит якорем, времена внутри пересчитываются `новое = якорь + (старое − якорь) × k` |
| кнопки `−1`…`+1` | пока выделение есть — двигают только его, иначе всю разметку как раньше |

Растягиваются не только начала строк, но и ручные концы (`line.end`
при `line.ручнойКонец`) и метки слов (`line.words[].time` и `.end`):
они заданы абсолютным временем, и без этого слова уехали бы от своих
строк. Считается всё **от снимка**, снятого при нажатии
(`снимокДиапазона`), а не от нынешних значений: иначе за одно
перетаскивание множители копились бы друг на друге и разметка уезжала
бы по экспоненте.

**Границы выделения — это МЕТКИ первой и последней строки**, а не размах
их блоков. Ручка стоит ровно на метке, поэтому край встаёт туда, куда
его привели, без всякого пересчёта. Конец блока для этого не годится:
его считает `lineSpan` от соседей, и на растяжении он бы «резинил» —
ручка уезжала бы из-под курсора. Размах вместе с ручными концами и
метками слов (`мин`/`макс` в `границыДиапазона`) нужен отдельно: им
выделение упирается в соседей.

**Ограничения:** выделение не налезает на соседние строки за его
пределами (упирается в конец предыдущей и начало следующей —
`пределыДиапазона`), `k > 0` и снизу зажат так, чтобы метки не
слиплись (`зажатьРастяжение`), времена не выходят за 0 и
`audio.duration`. Магнит применяется к тому краю, который тащат, а сами
выделенные строки из целей магнита исключены (`кромеСтрок`): иначе край
липнул бы к тому, что за него же и тащат.

**Видно это так:** на линейке — сиреневая полоса с двумя ручками по
краям, на всю высоту дорожки — лёгкая тень того же цвета, выделенные
блоки строк подсвечены и обведены сиреневым, а в списке строк выделенные
помечены справа (`.edit-row.in-range`). Сиреневый выбран потому, что все
остальные породы на дорожке заняты: розовый — оригинал, лаймовый —
строки, жёлтый — слова, голубой — голос. Подсказка у кнопок сдвига
меняется вслед за выделением (`обновитьПодписиРедактора`), иначе она
бы врала про «всю разметку».

**Отмена** обычная: снимок кладётся в стек в `beginRangeDrag`, ДО
изменения, пустой убирается `dropEmptyHistory`. `Cmd+Z` возвращает и
времена строк, и ручные концы, и метки слов — они все входят в снимок
`snapshotTimings`.

Самопроверка (раздел `диапазон`) держит всё это: протяжку по линейке,
ловлю ручек, сдвиг только выделенного, растяжение с проверкой числом
(середина обязана встать ровно посередине), поездку меток слов и ручных
концов вместе со строками, неприкосновенность соседей, упор в соседнюю
строку и возврат по отмене.

**Мышь.** Край блока тянет границу, середина — всю строку целиком.
Конец, сдвинутый мышью, помечается как ручной (`line.ручнойКонец`) —
дальше автоматика его не трогает. У слов тянется граница между соседями;
если строка ещё делилась автоматически, текущее деление сначала
записывается как настоящее (`ensureWords`), а потом двигается одна
граница. Пустое место дорожки перематывает — и не только щелчком: указатель
там **тащится**, и под ним звучит песня (см. «Слышимая перемотка»
ниже). Колесо прокручивает,
колесо с Cmd/Ctrl/Alt меняет масштаб вокруг курсора.

**Панель управления** над окнами: транспорт с часами слева
(`1:27,44 / 3:15,02`), дальше только значки — отмена, повтор, кольцо,
магнит, слышимая перемотка, сетка долей (у неё рядом ещё темп, смещение
и уверенность — см. «Сетка долей»), — потом четыре кнопки сдвига всей разметки (`−1`, `−0,1`,
`+0,1`, `+1`) и справа масштаб дорожки (отдалить, приблизить, вся
песня). Подписи «по кругу», «магнит», «сдвинуть всё», «масштаб» и «вся
песня» с кнопок ушли в подсказки: они занимали треть панели, а всё это
делается ещё и клавишами. Подсказки здесь свои, а не системные (см.
«Свои подсказки у кнопок» выше) — иначе кнопка со значком и без подписи
объясняла бы себя только тому, кто согласен ждать секунду. Подсказку у кнопок сдвига ставит кодом
`обновитьПодписиРедактора` — число в ней читается на двух языках
по-разному (`−0,1` против `−0.1`).

К словам это относится так же: обычное перетаскивание двигает стык,
с `Cmd`/`Ctrl` — только один край (см. «Пауза между словами» выше).

**Клавиши.** Пробел — играть/пауза, `↑` `↓` — соседняя строка
(с `Shift` — расширить выделение диапазона, см. выше), `←` `→` —
начало выбранной, `[` `]` — конец, `Shift` мельче (0,02 с), `Alt` крупнее
(1 с), `Enter` — прослушать строку, `L` — кольцо, `S` — притягивание,
`G` — сетка долей,
`Cmd+Z` / `Cmd+Shift+Z` — отмена и повтор, `+` `−` — масштаб. Клавиша
берётся по её **месту** (`e.code`), а не по букве: у русской раскладки
`Cmd+Z` — это `Cmd+я`.

**Под открытым окном клавиши редактора молчат целиком** (`окноПоверхСтудии`).
Беда, которую это лечит: человек открывал «Как пользоваться» поверх студии
и читал, а обработчик под окном продолжал работать — стрелки двигали начало
выбранной строки на 0,1 с за нажатие, `↑`/`↓` меняли выбор и снимали
выделение диапазона, `G` включала сетку долей, `L` и `S` — кольцо и магнит,
`Delete` убирал отрезок оригинала. Разметка портилась молча. Проверка
одна на все окна и живёт в одном месте: класс `guide-open` на `body`
(руководство), `#whatsnew` без `hidden` и любой `.export-overlay` без
`hidden` — а это разом все четыре окна ожидания (смена тональности,
разделение вокала, распознавание, экспорт видео), так что новое такое
окно попадёт под проверку само. Закрывать окно — дело его собственных
обработчиков `Esc`, они живут отдельно и работают по-прежнему.

**Отмена и повтор** (`pushHistory`, `undoEdit`, `redoEdit`) держат снимки
только времён: начала, концы, ручные концы, метки слов и признак `≈`.
Снимок кладётся в стек **перед** изменением. Текст строк в снимок не
входит намеренно: его правят прямо в поле, там работает обычная отмена
браузера, и мешать ей своей было бы хуже, чем не иметь её вовсе. Если
разметку пересобрали заново и число строк изменилось, стек сбрасывается —
старые снимки уже не о тех строках.

**Кольцо** (`tickLoop`) крутит отрезок «немного до строки — строка —
немного после» и держит вокал включённым: подгонять на слух иначе не
выйдет. При уходе с шага кольцо гасится.

#### Слышимая перемотка

Указатель переставлялся **молча**. Человек вёл мышь и не слышал, где
он: место в песне искали глазами по волне, отпускали, слушали,
поправляли, снова отпускали. В монтажных программах под ползущим
курсором играет короткий кусочек звука, и место находится на слух
за секунду. Теперь так и здесь.

**Где звучит.** Пока тащат указатель (по волне или по любому пустому
месту дорожки — это новое перетаскивание `seek`, раньше щелчок просто
переставлял время) и пока тащат границу строки, слова, отрезка
оригинала или края выделенного диапазона. Время берётся из подписи
у курсора (`editor.dragTip`) — её ставят все виды перетаскивания,
так что граница обошлась даром.

**Как устроено** (`скраб`, `скрабнуть`, `собратьКусочекСкраба`
в `app.js`). Каждое движение мыши просит проиграть кусочек длиной
`СКРАБ_ЗЕРНО` = 60 мс, начиная с точки под курсором. Кусочек — это
свой `AudioBufferSourceNode` (один на оригинал, второй на минусовку,
если её слышно), своё усиление на каждый и общий **конверт**: узел
усиления, который на входе кусочка поднимается с нуля до единицы за
`СКРАБ_ФЕЙД` = 5 мс и на выходе так же уходит в ноль
(`linearRampToValueAtTime`).

**Почему не щёлкает.** Резкий старт буфера — это разрыв волны:
отсчёт скачком уходит с нуля на амплитуду сигнала, и ухо слышит его
громче музыки. Именно от этого конверт: волна выходит из нуля и в ноль
же возвращается, скакать нечему. Второе — кусочки идут **встык, а не
внахлёст**: следующий ставится ровно туда, где кончается предыдущий
(`скраб.конец`), поэтому наложения двух кусков не бывает вовсе — ни
суммы двух сигналов, ни перегруза, ни фазовой каши. Досрочная
остановка (заиграло обычным ходом, ушли с шага, выключили) тоже идёт
затуханием, а не обрывом.

**Почему не копятся узлы.** Пока предыдущий кусочек не доиграл
(с запасом `СКРАБ_ЗАПАС` = 12 мс), новый не запускается вовсе — то
есть не чаще одного на ~50 мс, сколько бы событий мыши ни пришло.
Сверху ещё страховка: больше `СКРАБ_МАКС` = 3 живых источников не
держим. Доигравший убирает себя сам (`onended` → `disconnect`).

**Скраб — это МОНИТОРИНГ**, как соло и уровни дорожек: живёт только
в редакторе и только в живом плеере, идёт отдельным путём мимо общей
цепи. Обычное воспроизведение (`audio.play`/`pause`), запись видео и
выгрузка `.wav` о нём не знают. Эквалайзер и лимитер он тоже обходит:
это разовые 60 мс на поиск места, а лишние узлы на каждый кусочек —
лишний повод для щелчка. Играет звук обычным ходом — скраб молчит:
и так слышно.

**Звучит тем же, чем звучит песня.** Усиления берутся из
`усиленияСейчас` — той же функции, что кормит общую цепь (раньше
этот выбор жил внутри `applyMix`, теперь вынесен). Слушают один
минус — скраб будет минусом, включили соло «только голос» — будет
голос. Иначе выходило бы, что подпевка звучит одним, а перемотка
другим.

**Скиммирование: звук при простом наведении.** В монтажных программах
место в записи ищут не перетаскиванием указателя, а движением мыши над
дорожкой: звук идёт под курсором, а указатель воспроизведения стоит
там, где стоял. Так быстрее — не надо ни нажимать, ни возвращать
указатель обратно. Делает это `скиммировать` в `app.js`, вызываемая
из `pointermove` дорожки; движок и выключатель те же самые.

Отличие от перетаскивания одно, зато важное: **наведение сыплет
событиями заметно чаще**. Порог у `скрабнуть` на это и рассчитан (пока
предыдущий кусочек звучит, новый не запускается), но своя защёлка по
часам всё равно нужна — `СКИММ_ПАУЗА` = 45 мс: иначе каждое из сотни
движений в секунду поднимало бы звуковой контекст и считало усиления
впустую. И ещё: контекста, которого ещё нет, наведением **не заводим** —
звук должен начинаться с действия человека, а не с проезда мышью.
Ушли с дорожки (`pointerleave`) — скиммирование гаснет затуханием.
Играет звук обычным ходом — молчит, как и скраб.

**Включатель** — кнопка со значком указателя и волн рядом с магнитом
(`tl-scrub`, `editor.слышнаяПеремотка`, `setScrub`). Один и тот же
у перемотки и у скиммирования: два органа управления об одном и том же
были бы хуже, чем отсутствие второй возможности вовсе.

**По умолчанию выключено.** Звук под курсором помогает не всем, а
заводился он сам собой: достаточно провести мышью над дорожкой. Поэтому
кнопка стоит невдавленной, как кольцо и сетка долей, и включается
руками, как магнит; подсказка на обоих языках говорит прямо: «По
умолчанию выключено — нажми, чтобы включить». Выключенный режим гасит
и то, что звучит прямо сейчас.

Самопроверка — раздел `скраб`. Она не смотрит на кнопку, а **считает**:
собирает два кусочка встык тем же кодом, каким они играют в колонки,
отрисовывает в `OfflineAudioContext` и меряет наибольший скачок между
соседними отсчётами на входе, на стыке и на выходе. Синус берётся во
весь голос и режется ровно по пику — без затухания кусочек начинался бы
скачком на 0,8. С затуханием `скачокНаСтыке` = 0,0251 при
`скачокВЗвуке` = 0,0251, то есть переход ровно такой же пологий, как
сама волна; убери конверт — и признак сразу показывает 0,8 (проверено
подсовыванием регрессии). Там же числами: во время воспроизведения
скраб не запускается, вне редактора тоже, выключатель выключает,
тридцать движений мыши подряд дают ровно один кусочек, а после
проигрывания живых источников не остаётся ни одного. Скиммирование
проверяет отдельный раздел `скиммирование`: сотня движений подряд —
ровно один кусочек, указатель воспроизведения при этом не сдвинулся
ни на йоту, во время воспроизведения и при выключенной перемотке
скиммирование молчит, а контекста, которого ещё нет, наведение
не поднимает.

#### Сетка долей

Куплеты идут по долям, и границы строк почти всегда попадают на долю.
Если доли видны на дорожке и к ним липнет магнит, разметка встаёт ровно
и быстро. Беда одна и известна заранее: **автомат может ошибиться
с темпом**, а ошибившийся темп хуже, чем никакого — он тащит границы
туда, где их быть не должно, и портит уже проверенную руками разметку.
Поэтому:

* **сетка выключена по умолчанию.** Пока она выключена, в поведении
  дорожки не меняется ровно ничего: линии не рисуются, доли не
  притягивают, точек магнита не прибавляется;
* включает её человек **сам**, увидев, какой темп нашёлся;
* **оба числа правятся руками** — темп и смещение первой доли. Без
  этого при промахе автомата сеткой нельзя было бы пользоваться вовсе.

**Как считается темп** (`tempo.js`, счёт в рабочем потоке), по минусовке,
а если её ещё нет — по оригиналу. На входе — **спектральный поток начал**,
а не огибающая громкости, и это главное:

1. **прореживание** до ~11 кГц (`ТЕМП_ЗВУК`) усреднением по отсчётам:
   выше 5 кГц про доли ничего нового нет, а считать вчетверо дешевле;
   усреднение заодно работает фильтром против наложения частот;
2. **КПФ** окном Ханна в `ТЕМП_ОКНО` = 1024 отсчёта (≈93 мс) с шагом
   5 мс (`ТЕМП_ЧАСТОТА` = 200 кадров в секунду). Преобразование —
   общее с тональностью, `fft.js`; два соседних кадра едут через одно
   КПФ (чётный в вещественную часть, нечётный в мнимую), как в вокодере
   левый и правый каналы;
3. **логарифмическое сжатие каждой полосы**: log(1 + 1000·|X|). Без него
   поток считал бы только громкие полосы — бочку и малый барабан, —
   а тихая гитара, входящая ровно по доле, не весила бы ничего;
4. **поток начал** — сумма только ПОЛОЖИТЕЛЬНЫХ приращений по всем
   полосам: появление новой энергии в полосе и есть начало звука,
   затухание после удара — нет;
5. **автокорреляция** потока по лагам, отвечающим 60–190 ударам в минуту
   (`ТЕМП_МИН`/`ТЕМП_МАКС`): у ритмичной музыки поток похож сам на себя
   ровно через долю;
6. **предпочтение обычного темпа** (`весТемпа`): ровные щелчки одинаково
   хорошо объясняются и шестьюдесятью, и ста двадцатью ударами, и без
   этого веса выбор между ними был бы случайным. Клоним к 120
   (`ТЕМП_ЦЕНТР`) — так поступают все счётчики темпа;
7. **гребёнка** — уточнение периода и фазы вместе: автокорреляция даёт
   период с точностью до кадра, а этого мало — ошибка в сотую долю кадра
   за две минуты разводит сетку с музыкой на полтакта. Перебираем период
   мелким шагом вокруг найденного и вместе с ним фазу, складывая поток
   ровно там, где сетка ставит доли, и делим на число долей, чтобы более
   частая сетка не выигрывала одним числом слагаемых.

**Почему спектр, а не громкость.** Раньше тут была огибающая энергии
в трёх полосах, и на щелчках она работала безупречно — а на настоящей
музыке уверенность выходила 5–8 %. Причина в сведении: компрессор
ровняет громкость, гитары и голос заполняют паузы, и между ударами она
почти не проседает — вершина автокорреляции у «Кирпичей» была не выше,
чем у белого шума. Спектральный поток смотрит не на громкость, а на
**появление новой энергии в отдельных полосах**: удар барабана — это
всплеск сразу в сотне полос, даже если общий уровень не шелохнулся,
потому что ровно в этот миг чуть притих кто-то другой. Замерено на тех
же файлах (первые 120 секунд, `?v=` сброшен, время — на нашей машине):

| запись | было: BPM / фаза / уверенность / время | стало |
| --- | --- | --- |
| `kirpichi96.mp3`, рэп | 126,69 / 0,189 / **9 %** / 59 мс | 126,73 / 0,392 / **41 %** / 523 мс |
| та же минусовка от UVR5 | **93,66** / 0,526 / **9 %** / 56 мс | **126,71** / 0,392 / **44 %** / 504 мс |
| «Я так люблю тебя Ленинград» | 99,28 / 0,230 / **7 %** / 72 мс | 100,04 / 0,418 / **47 %** / 630 мс |
| ровные щелчки 120 | 120,00 / 0,100 / 50 % | 120,00 / 0,106 / 50 % |
| белый шум | — / — / 6 % | — / — / 4 % |
| тишина | темпа нет (`null`) | темпа нет (`null`) |

Отдельно про вторую строку. Песня и её собственная минусовка обязаны
давать один темп — это самая простая проверка на вменяемость счётчика,
и по громкости она НЕ проходила: 126,7 против 93,7. По спектральному
потоку обе дают 126,7 и одну и ту же фазу, с точностью до сотых. Ради
той же беды когда-то и заводились три полосы вместо одной; теперь они
не нужны — полос у спектра пятьсот двенадцать.

**Задержка окна** — то, о чём легко забыть и получить сетку, съехавшую
на десятую долю секунды. Кадр КПФ смотрит на 1024 отсчёта назад, и новая
энергия попадает в него не тогда, когда удар случился, а когда он ВЪЕХАЛ
в окно. Поэтому кадр относится не к своему левому краю, а к середине
того куска, который в него только что вошёл — на (`ТЕМП_ОКНО` − шаг/2)
отсчётов правее. Без поправки щелчки, поставленные на 0,10 с, находились
на 0,015 — ровно на длину окна раньше.

**Что означает уверенность.** Это доля потока, которая объясняется
повторением ровно через найденный период: автокорреляция нормирована,
так что `ак[лучший]` — обычный коэффициент корреляции от 0 до 1.
Отсчитываем от **фона** (среднего совпадения по всей полосе перебора:
столько набегает само собой, без всякого ритма) и делим на потолок
`ТЕМП_ПОТОЛОК` = 0,6 — выше него совпадение уже безоговорочное, единицы
не достигает даже идеально ритмичная запись. Двойственный темп
уверенности не прибавляет: там она делится пополам.

Через разброс (z-мера, «на сколько сигм вершина выше фона») пробовали —
не годится: на шуме выходило 2,3, на «Кирпичах» 1,9, то есть настоящая
музыка выглядела ХУЖЕ шума. У музыки, кроме вершины на доле, есть
вершины на полудоле и на такте, и они же раздувают разброс. Он меряет
богатство ритма, а не выраженность доли.

**Какому числу верить.** Выше 60 % (зелёное) — включай не глядя.
30–60 % (жёлтое) — обычная настоящая музыка, число почти наверняка
верное, но линии на дорожке стоит сверить с ударами глазами. Ниже 30 %
(красное) — счётчик не нашёл ритма: скорее всего запись без выраженной
доли, и темп лучше набрать руками. Отдельно смотри на подсказку про
двойственность: она значит, что вдвое быстрее или вдвое медленнее
подходит почти так же хорошо.

**Почему в рабочем потоке.** Спектральный поток стоит дорого: на песне
в три минуты это двадцать четыре тысячи преобразований Фурье, 500–630 мс
против 60–70 мс у прежней огибающей. Полсекунды замершего окна при
открытии редактора — это заметно, поэтому счёт уехал в рабочий поток
(`tempo.js` умеет работать и модулем в окне, и потоком: одна копия
алгоритма вместо двух). Окна прогресса нет нарочно — ждать нечего:
редактор открывается сразу, показатель уверенности стоит на «…»
и сменяется числом, когда поток ответит. Заказы нумеруются, и ответы
разбираются по номеру: они накладываются легко — открыли редактор, тут
же досчиталась минусовка, — и без номера второй заказ отбирал бы ответ
у первого. Поток не завёлся (старый браузер, запрет политики
безопасности) — считаем на месте: лучше замереть на полсекунды, чем
остаться без темпа вовсе.

Считается **один раз на песню** и кладётся в кэш (`editor.темпАвто`) —
как огибающая волны `editor.peaks`; при смене песни кэш сбрасывается,
при появлении минусовки оценка переснимается по ней. Разбираются первые
`ТЕМП_ОТРЕЗОК` = 120 секунд по одному каналу: на всей песне перебор шёл
бы вчетверо дольше, а темп от этого не меняется. Опоздавший ответ
проверяет, та ли ещё песня: за полсекунды человек успевает открыть
другую, и переписывать её темп чужим числом нельзя.

**Двойственность не замалчивается.** Если вдвое медленнее (или вдвое
быстрее) совпадает почти так же хорошо, поднимается признак
`двойственный`, а уверенность делится пополам. Честнее сказать «может
быть и вдвое медленнее», чем молча выбрать одно из двух: подсказка
у показателя прямо предлагает поделить темп надвое или умножить на два.

**Что видно.** Рядом с включателем (кнопка `tl-grid`, значок сетки,
клавиша `G`) стоят два поля и показатель уверенности: `120,0 BPM`,
`0,06 с`, `50 %`. Пока темп считается в рабочем потоке, на месте
показателя стоит `…` — прочерк тут врал бы, он значит «темпа нет».
Цвет показателя сам по себе ответ на вопрос «можно ли
верить»: зелёное включают не глядя, красное лучше проверить. Поправленный
руками темп помечается словом «своё» — с этого мгновения автомат его
не перебивает, а двойной щелчок по полю возвращает найденное автоматом
(та же привычка, что у ползунков дорожек).

Пока в поле **набирают**, панель его не перезаписывает — иначе набранное
пропадало бы из-под пальцев. Но когда темп меняют **не из этого поля**
(двойной щелчок, пересчёт, открытие проекта или черновика),
`обновитьСетку(силой)` снимает и пометку «набирают», и красную рамку:
поле обязано показывать то, что и правда действует. Раньше без этого
негодное число залипало насмерть — набрал `9999`, нажал Enter (поле
краснеет, верно), тут же двойным щелчком попросил найденное автоматом:
темп применялся, сетка рисовалась по нему, а в поле оставалось красное
`9999`. Орган управления показывал одно, звучало другое.

**Включатель переживает перезагрузку отдельно от темпа** (`сеткаИзПроекта`).
Раньше признак `вкл` читался только внутри ветки с годным `bpm`: включил
сетку на записи, где темп не определился, — и после перезагрузки кнопка
сама выключалась. Включатель — про желание человека, а не про число;
включённая сетка без темпа ничего не рисует и никого не притягивает
(`сеткаДолей` вернёт `null`), зато `setBeatGrid` при первой возможности
темп досчитает.

**Что делать при промахе.** Включить сетку, посмотреть на дорожку: линии
обязаны попадать на удары волны. Не попадают — набрать свой темп в поле
`BPM` (частая ошибка — вдвое: попробуйте удвоить или поделить пополам),
а потом свести первую линию с первым ударом полем смещения. На настоящей
плотной музыке уверенность выходит средней — 40–47 % (обе песни из
«Материалов для проверки»: 126,7 и 100,0), и это честный ответ: доля там
выражена, но не так, как у метронома. Раньше на том же материале
выходило 5–8 % — счёт шёл по огибающей громкости, и она на плотном
сведении доли почти не видела. Сверить линии с ударами глазами всё равно
надо — ровно поэтому сетка и не включается сама.

**Как рисуется** (`drawBeatGrid`): тонкие вертикальные линии поверх
волны, но **под** блоками строк и слов — сетка это подложка, разметку
она заслонять не должна. Сильная доля такта (каждая четвёртая,
`ДОЛЕЙ_В_ТАКТЕ`) ярче слабых: замерено по пикселям — 255 против 133 при
фоне 66. Когда линии встают чаще, чем раз в `ДОЛЯ_МИН_ПИКС` = 6 пикселей,
они не рисуются вовсе: сначала пропадают слабые доли, потом и такты.
На всю песню (2,5 пикселя в секунду) сетки не видно — там от неё
осталась бы каша.

**Притягивание.** Доля — ещё одна порода точек магнита (`точкиМагнита`),
и **самая слабая**: `ВЕС_МАГНИТА.доля` = 4, слабее края песни. На равном
расстоянии её перебивает и указатель, и строка, и отрезок, и голос —
темп определён автоматом и не имеет права спорить с тем, что человек
поставил сам. Долей в песне тысячи, и складывать все в список на каждом
кадре перетаскивания было бы расточительством, поэтому берутся только
две ближайшие к тому месту, куда привели мышь (`около`, ставит
`примагнитить`).

**Что сохраняется.** Темп, смещение, пометка «поправлен руками» и сам
выключатель уходят в проект ключом `grid` (`собратьПроект`,
`сеткаИзПроекта`) — то есть и в `localStorage`, и в черновик `.kpunch`.
В проектах постарше ключа нет вовсе: `сеткаИзПроекта` отдаёт умолчания,
и ничего не ломается.

Самопроверка — раздел `сеткаДолей`. Она не смотрит на кнопку, а
**считает**: собирает щелчки ровно через известный промежуток на частоте
22 000 и требует именно этот темп и именно эту фазу. Числа замера:
120 ударов → `bpm` 120,00 и `фаза` 0,1056; 60 ударов → 60,00 и 0,2056;
90 ударов → 89,99 и 0,3312 (истинные фазы 0,1 / 0,2 / 0,33, допуск
0,02 — им же проверяется поправка на задержку окна). Удвоение
проверяется отдельно: у ровных
щелчков 120 половинный темп подходит ровно так же, и признак
`двойственный` обязан это признать (признаёт, уверенность падает
до 0,5), а у 60 такого соперника нет — там он обязан молчать (молчит).
Тишина даёт `null`, а не выдуманный темп.

**Шкала уверенности проверяется числами, на трёх видах материала.**
Чёткий ритм — 100 % (щелчки 60 и 90), белый шум — 8 % (порог: ниже
25 %), тишина — темпа нет вовсе. Между ними стоит **перекличка**: две
шумовые полосы (400–700 и 900–1200 Гц) меняются местами каждые 0,6 с
плавным переходом равной мощности. Общая громкость на ней гуляет
случайно и про долю не говорит ничего — меняется только спектр, — а обе
полосы лежат внутри одной полосы прежнего трёхполосного разбора, так
что материал ровно про то, ради чего всё и затевалось. Требуется
100,0 удара (истинные 100), фаза 0,110 (истинная 0,1) и уверенность
выше 0,9; выходит 100,01 / 0,1104 / 1,0. Три регрессии подсунуты
и проверены: убери логарифмическое сжатие полос — фаза уезжает на 0,140
и раздел краснеет; верни широкополосную огибающую — выходит 77,5 удара
и 16 %, краснеет; сделай шкалу щедрой (потолок 0,05 вместо 0,6) — белый
шум получает 93 % и краснеет тоже. Дальше числами: при
выключенной сетке `примагнитить(7.49)` возвращает ровно 7,49 и ни
к чему не липнет, при включённой — 7,50 с видом «доля»; на равном
расстоянии выигрывают «строка» и «указатель»; поправленный руками
темп 137,5 переживает и сохранение проекта, и пересчёт автомата;
проект без ключа `grid` даёт выключенную сетку без темпа. И здесь обе
регрессии подсунуты и проверены: сделай долю сильнее строки — раздел
краснеет, заставь сетку не смотреть на выключатель — краснеет тоже.

### Простукивание: режим, а не шаг

Отдельного шага «Синхронизация» нет. Простукивание пробелом — режим
внутри редактора (`startTapMode` / `tapHit` / `finishTapMode` в `app.js`).
Пока он включён, панель шага получает класс `tapping`, и список строк,
просмотр, панель выбранной строки, инструменты дорожки и кнопки
перехода уходят с глаз. Остаются: крупная текущая строка, следующая
помельче, счётчик «размечено N из M», время, дорожка — на ней метки
появляются на глазах — и две кнопки, «отменить последнюю» и «готово».

Режим включается сам, когда времён нет вовсе: на сайте простукивание —
единственный способ разметки, нейросетей там нет, и прятать его за
кнопкой незачем. В приложении после подгонки текста времена уже есть,
и редактор открывается обычным видом.

**Правила переписывания меток.** Человек не должен бояться, что потеряет
работу, поэтому:

* стучать можно с любого места, метки раньше него не трогаются;
* **ничего не стирается заранее** — метка переписывается ровно в тот
  момент, когда по строке ударили. Строки, до которых не дошли, остаются
  как были. Раньше вход в простукивание с середины стирал всё до конца
  песни;
* каждый удар отменяется по отдельности («отменить последнюю», она же
  `Backspace`): строка возвращается к прежнему времени, а песня
  отматывается назад, чтобы попробовать ещё раз;
* весь заход целиком снимается общей отменой `Cmd+Z` — снимок всех
  времён кладётся в стек один раз, перед первым ударом. `Cmd+Z` прямо
  посреди захода сначала закрывает режим, потом откатывает.

Заход можно закончить посреди песни, и тогда дальше остаются метки из
прошлой разметки — иногда **раньше** только что простуканных. Молча
ломать караоке нельзя, но и стирать чужую работу без спроса тоже:
`проверитьПорядокПослеЗахода` замечает такой стык и спрашивает.
Стирание попадает в тот же снимок отмены.

### Чего нет у бесплатных редакторов: разметка по голосу

Огибающая голоса даёт редактору то, чего не даёт волна общего микса:
**видно, где поют**. По волне микса вступление голоса не отличить от
вступления гитары, и метки приходится ставить на слух. На полосе голоса
кусок пения виден глазами, и граница строки ставится по нему.

Поверх этого — магнит (`примагнитить`, кнопка со значком магнита, клавиша
`S`, зажатый `Alt` отключает на время перетаскивания — как в Logic Pro и
Final Cut). Пока тянешь границу, она прилипает к краям соседних строк,
к указателю воспроизведения, к границам отрезков оригинального вокала,
к началу и концу куска пения, к краям песни и — если включена сетка долей
(см. выше) — к самим долям, если цель ближе двенадцати
пикселей. При равном расстоянии выигрывает более важная порода: указатель,
затем строки и отрезки, затем голос, затем край, и в самом конце доля. Окно считается в пикселях,
а не в секундах: чем крупнее масштаб, тем точнее выходит и притягивание.

Отдельно стоит помнить про подтяжку самой сцены: `lineStart` двигает
начало строки к вступлению голоса в окне ±0,7 с (±1,5 с для `≈`).
Поэтому блок иногда «не идёт» за мышью — его держит голос. Чтобы это
не выглядело поломкой, своё время строки рисуется синим пунктиром внутри
блока, когда оно разошлось с тем, что покажет сцена.

**Без огибающей** — на сайте всегда, в приложении до удаления вокала —
полоса голоса просто не рисуется, дорожка становится ниже на 34 пикселя
(`timelineLanes`), притягивание ничего не делает, подтяжки начала нет,
и границы встают ровно туда, куда их привели. Всё остальное работает
как обычно.
