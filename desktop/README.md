# Бэнэнгская Рапсодия — настольная версия

Караоке-студия с удалением вокала нейросетью. Всё считается на твоём
компьютере: ни звук, ни текст никуда не отправляются.

## Что умеет

Те же пять шагов, что и на сайте — песня, текст, синхронизация, редактор
с дорожкой, караоке, — плюс главное отличие настольной версии:

**🧠 Убрать вокал нейросетью** (шаг «Песня») — модель HTDemucs, та же,
что стоит за UVR5. Качество несопоставимо с вычитанием центрального канала.

Три способа получить минусовку остались на выбор:
1. Встроенное приглушение — мгновенно, качество среднее
2. Свой файл — если уже прогнал трек через UVR5 отдельно
3. Нейросеть прямо в приложении — лучшее качество без лишних программ

## Установка

- **macOS (Apple Silicon)**: `Бэнэнгская Рапсодия-1.0.0-arm64.dmg`
- **Windows (x64 и ARM)**: `Бэнэнгская Рапсодия Setup 1.0.0.exe`

Сборки не подписаны сертификатом разработчика, поэтому при первом запуске
система будет ругаться:

- **macOS**: правый клик по приложению → «Открыть» → «Открыть» ещё раз.
  Через Launchpad или двойным кликом в первый раз не откроется.
- **Windows**: SmartScreen покажет синее окно → «Подробнее» → «Выполнить в любом случае».

## Модель

При первом нажатии «Убрать вокал» приложение предложит скачать модель —
172 МБ, один раз. Дальше она лежит на диске и интернет больше не нужен:

- macOS: `~/Library/Application Support/Бэнэнгская Рапсодия/htdemucs.onnx`
- Windows: `%APPDATA%\Бэнэнгская Рапсодия\htdemucs.onnx`

## Сколько ждать

Замерено на Apple M-серии, 8 потоков: **примерно 2 минуты на трек в 3 минуты**.
На Windows скорость зависит от числа ядер. Прогресс и оставшееся время
показываются в окне, расчёт можно отменить.

## Разработка

```bash
npm install                # ставит зависимости и раскладывает движок ONNX
npm start                  # запуск
npm run dist:mac           # сборка dmg для Apple Silicon
npm run dist:win           # сборка exe для Windows
npm run sync               # перенести интерфейс из веб-версии (../)
```

Файлы движка ONNX (39 МБ) в репозитории не хранятся — их раскладывает
`setup-ort.js` после `npm install`. Интерфейс — копия веб-версии из корня
репозитория: правь там, потом `npm run sync`.

Самопроверка без ручных кликов:

```bash
KARAOKE_SELFTEST=1 KARAOKE_E2E=1 npm start
```

Проверяет интерфейс, наличие модели и прогоняет реальное разделение на
25 секундах звука, после чего закрывается.

## Как это устроено

- `main.js` — окно, скачивание модели, отдача файлов через схему `app://`
  с заголовками изоляции (без них WebAssembly считает в один поток вместо восьми)
- `renderer/separator-worker.js` — разделение в фоновом потоке окна
- `renderer/dsp.js` — БПФ, оконное преобразование и обратное к нему;
  соглашения повторяют `torch.stft` с параметрами обучения Demucs

Расчёт идёт на WebAssembly-версии ONNX. Нативный `onnxruntime-node` внутри
Electron падает с SIGTRAP при загрузке модели — проверено во всех трёх режимах
(utilityProcess, worker_threads, ELECTRON_RUN_AS_NODE), поэтому от него отказались.
Ускорение через CoreML тоже отпало: вся выдача становится нечисловой.

основана на [Demucs](https://github.com/adefossez/demucs) от Meta (MIT).
